# 자취달력(JachiCal) — PRD (제품 요구사항 정의서)

> 본 문서는 개발 지시서 Section 0에서 **확정된 기획**을 기록으로 고정한 것입니다.
> "왜(Why) 만드는가"에 해당하며, 이후 모든 단계(UI/UX·아키텍처·개발)의 상위 기준입니다.
> 이 문서의 용어·기능 범위(MoSCoW)는 이후 단계에서 임의 변경하지 않습니다.

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 서비스명(가칭) | 자취달력 (JachiCal) |
| 한 줄 정의 | 흩어진 공과금 납부일과 지출을 한 곳에서 관리하는 자취생용 생활 캘린더 |
| 타겟 유저 | 자취 1~3년 차 대학생 (페르소나: 김서연, 22세) |
| 플랫폼 | 모바일 우선(Mobile-first) 반응형 웹 |

## 2. 해결하려는 문제 (Why)

- 전기·가스·수도·관리비의 **납부처·납부일·주기가 제각각**이라 놓치기 쉽다 → 연체료/불이익.
- 지출 관리 앱은 **입력이 무거워** 자취생이 3일 이상 유지하기 어렵다.
- 자취 초기 행정 절차(전입신고·전기 명의변경 등)를 **언제 뭘 해야 하는지** 모른다.

## 3. 타겟 사용자 (페르소나)

**김서연 (22세, 대학 3학년, 자취 2년 차)**
- 고정비를 대략만 알고, 납부일은 문자/고지서가 와야 인지한다.
- 가계부 앱을 몇 번 깔았지만 입력이 귀찮아 3일 내 이탈.
- "이번 달 얼마 남았지?"를 즉답할 수 있길 원한다.

## 4. 핵심 기능 및 우선순위 (MoSCoW)

| 구분 | 기능 | 설명 |
| --- | --- | --- |
| **Must** | F1. 공과금 통합 캘린더 | 전기·가스·수도·관리비 납부일 통합 + 납부 알림 + 납부 완료 체크 |
| **Must** | F2. 간편 예산 관리 | 수동 입력 기반, 월 예산 대비 잔여금 게이지 시각화 |
| **Must** | 사용자 인증 | 최소 기능(가입/로그인) — 데이터 소유 단위 |
| **Should** | F3. 자취 행정 타임라인 | 전입신고·명의변경 등 체크리스트 |
| **Could** | (차기) 카드 문자 자동 연동, 집안일 체크리스트 | 1차 MVP 제외 |
| **Won't** | 결제 대행, 은행 계좌 직접 연동, 카드 문자 자동 연동 | 1차 MVP 비목표 |

## 5. 기대 효과 / 핵심 지표 (KPI)

| KPI | 목표 |
| --- | --- |
| 납부 알림 클릭률 | 60% ↑ |
| 지출 기록 3일 연속 유지율 | 40% ↑ |
| WAU/MAU (주간/월간 활성 비율) | 35% ↑ |

## 6. 비목표 (1차 MVP 제외)

- 결제 대행 / 은행 계좌 직접 연동 / 카드 문자 자동 연동
- 다인(공유) 가계부, 소셜 기능

## 7. 용어 정의 (이후 단계 공통 사용)

| 용어 | 정의 |
| --- | --- |
| 공과금 항목(Bill) | 사용자가 등록한 정기 납부 대상 (전기/가스/수도/관리비/기타) |
| 납부 이력(Payment) | 특정 월의 공과금 항목에 대한 납부 완료/예정 기록 |
| 예산(Budget) | 월 단위 지출 상한 목표 금액 |
| 지출(Expense) | 사용자가 수동 입력한 개별 지출 기록 |
| 행정 태스크(AdminTask) | 자취 행정 타임라인 체크리스트의 개별 항목 |
