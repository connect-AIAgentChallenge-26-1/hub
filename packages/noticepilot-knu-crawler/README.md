# NoticePilot KNU Crawler v0.4.4

This package validates a local pipeline for Kangwon National University public notices:

```text
KNU notice list/detail crawl
→ normalized notice JSON
→ calendar candidate JSON
→ static .ics export
→ optional campus feed profile export
```

v0.4.4 keeps the v0.4.3 campus-aware pipeline and adds **feed profile presets** so crawler/export outputs can be generated by campus profile without hard-coding CLI flags in the frontend or caller.

### Policy.15 local semantic ownership

Policy.15 does not broaden generic regex matching. It resolves locally explicit schedule meaning before applying inherited title or continuation context:

- `시험 대상자 발표`, `재입학 허가 통보`, and `지원대상자 확정통보` are result announcements, not exams or application periods;
- `수업평가` is an academic evaluation window, not an exam;
- exact `수강기간`, `실습기간`, `이용기간`, and operational extension windows are activity events;
- activity periods with an exact start but vague end remain review-only;
- refund, return, scholarship deposit, and payment-schedule reference dates are not student actions;
- explicit additional-confirmed, registered, waiting-payment, or other conditional status groups are review-only;
- internal document evaluation/selection points are review-only;
- a real course-registration cancellation window remains actionable even when its consequence says tuition is fully refunded.

See `POLICY_0_1_13_CORPUS_DIAGNOSIS.md`.

### Policy.11 hardened academic action and applicability contract

- Leave-of-absence and return-from-leave application windows are always represented as `academic_period` candidates.
- A shared `휴학 및 복학` period is preserved as two candidates with distinct `actionType` values.
- Course-registration actions distinguish regular, preliminary, change, and cancellation windows.
- Explicit undergraduate/graduate, student-year, enrollment-status, and admission-type applicability is stored in `audienceRules`.
- Year-specific course-registration rows are split into separate candidates instead of being merged into a broad date range.
- Candidates with the same date remain distinct when their `actionType` or `audienceRules` differ.
- Actual user-profile filtering remains the responsibility of the downstream subscription feed builder; the generic preview feed continues to include every publishable student candidate.

Example candidate fields:

```json
{
  "eventType": "academic_period",
  "actionType": "course_registration",
  "audienceRules": {
    "degreeLevels": ["undergraduate"],
    "studentYears": [3],
    "enrollmentStatuses": [],
    "admissionTypes": [],
    "matchMode": "all_dimensions",
    "personalizationReady": true
  }
}
```

### Policy.9 semantic guards inherited by policy.15

- reference/revision dates such as `공고일(... ) 기준` and `수정(...)` are not calendar actions;
- `1.23.~27.` style same-month ranges retain the omitted-month end;
- multiple independent dates and recurring daily time windows are review-only until occurrence expansion exists;
- truncated date fragments ending with an unmatched weekday parenthesis are review-only;
- general-public events and practicum-host recruitment are excluded from the student-first feed.
- decimal scores, grade-table values, and named historical dates are not schedule tokens;
- slash-separated independent dates are review-only until occurrence expansion exists;
- exact activity periods are events, while partial activity periods are review-only;
- term-end, document-release/share, grade-transmission, and eligibility reference dates are not user actions;
- result announcements remain publishable, but selected-participant-only follow-up actions are review-only.

### Candidate integrity and feed guards (policy.15)

- Fractions, scores, and numbered headings that resemble dates are rejected before candidate creation.
- A range is accepted only when two adjacent date tokens are directly connected by a range marker.
- Segments containing multiple independent schedules fail closed into the review path.
- Any residual reversed range is removed from feeds and recorded in `derived/mvp-policy-v0.1/reports/candidate-integrity.json`.
- Same-day clock ranges preserve both times; `24:00` is normalized safely.
- An omitted range-end year inherits the range-start year and rolls only across New Year.
- A time written only after the range end no longer leaks backward to the start date.
- Mixed date/timed-deadline ranges use local midnight for the start and retain the exact end clock.
- Completed result notices never publish to the broad student feed; explicit selected-participant follow-up actions are review-only.
- Redundant same-action boundary dates are consolidated, while conflicting same-action dates are demoted for review.
- Revision timestamps, eligibility reference dates, and internal selection periods are not calendar actions.
- Timed body evidence supersedes a same-day all-day title duplicate.
- Department-to-administration forwarding deadlines are excluded from the student feed and retained for review.
- `review-queue.jsonl` includes embedded review candidates from otherwise publishable notices.

### Policy.10 cumulative scope

Policy.10 retains the policy.9 local-context and actor guards and adds semantic
protection for score/history numerics, independent slash-separated schedules,
non-action reference dates, selected-participant-only follow-ups, and activity
period semantics. Cross-board reconciliation remains a separate downstream
stage.
