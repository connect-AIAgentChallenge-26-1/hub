# 과제 PR 생성 절차

`connect-AIAgentChallenge-26-1/hub`(upstream)에 제출하는 과제 PR을 만들 때 쓰는 절차.

## 1. 사전 확인

```bash
git status                 # 커밋 안 된 변경이 없어야 함
git log --oneline -10      # 이번 PR에 담길 커밋 확인
```

- 커밋 안 된 변경이 있으면 먼저 정리한다.
- **base 저장소 확인**: 이 프로젝트의 PR은 개인 fork(`sohyunll/hub`)에서
  upstream(`connect-AIAgentChallenge-26-1/hub`)으로 올라간다. 지금 작업 중인 로컬
  `campusfit/`은 아직 `hub` 저장소 구조(`N010_권소현/` 폴더) 밖에 있으므로, PR을 만들기
  전에 **`C:\Users\LG\Documents\hub`의 `N010_권소현/` 폴더로 옮겨야 하는지 사용자에게
  먼저 확인한다** — 대상 위치나 브랜치가 애매하면 진행하지 않고 묻는다.
- push가 필요하면 사용자에게 확인 후 push한다 — push 의사가 PR 요청에 포함됐는지
  애매하면 반드시 묻는다 (CLAUDE.md 절대 규칙: push·PR 생성은 요청 시에만).

## 2. 타이틀·본문 작성

- 타이틀: `[N010_권소현] - 이번 작업 한 문장 요약` (예: `[N010_권소현] - 웹 레이아웃 재설계 및 팀원모집 게시판 추가`)
- 본문: `.github/pull_request_template.md`의 5개 섹션을 전부 채운다.

| 섹션 | 작성 주체 |
|---|---|
| 주요 작업 리스트 | 커밋 로그·diff에서 요약해 작성. 스크린샷이 있으면 첨부 안내 |
| 내가 설명할 수 있는 부분 | **사용자에게 질문해서 사용자의 말로.** 코드/디자인 결정 한 곳을 골라 왜 그렇게 했는지. 대필 금지 — 학습 회고는 본인 것이어야 과제 의미가 있다 |
| 아직 이해 못 한 부분 | **사용자에게 질문해서 사용자의 말로.** 없다고 하면 "없음" |
| 새로 알게 된 것 | **사용자에게 질문해서 사용자의 말로** |
| 라벨 | 작업 성격에 맞는 걸 골라 제안하고 사용자 확인 후 지정 (아래 표 참고) |

회고 3섹션은 초안을 대신 써주지 않는다. 대신 이번 작업에서 물어볼 만한 지점을 질문으로
던지는 것까지만 한다. (슬랙에서 튜터님이 칭찬한 분의 PR을 참고해 추가한 규칙)

### 회고는 제품 문서가 아니라 이해도를 보여주는 곳이다

"주요 작업 리스트"가 캠퍼스핏이 뭘 했는지 보여주는 곳이라면, 회고 3섹션은 **사람이 얼마나
이해했는지**를 보여주는 곳이다 — 둘을 같은 걸로 착각하지 않는다. 그래서 질문을 던질 때:

- **하루 전체를 요약하게 하지 않는다.** 그날 diff에서 실제로 판단이 필요했던 지점 하나를
  골라 깊게 묻는다. 넓게 훑는 것보다 하나를 제대로 설명하는 게 이해도를 더 잘 보여준다.
  예: "온보딩에서 관심분야 단계를 지운 이유를 직접 설명할 수 있겠어요?",
  "row에 `.link`를 조건부로만 붙인 이유(팀원모집 행은 왜 뺐는지)를 설명할 수 있어요?"
- **"아직 이해 못 한 부분"은 솔직하게 쓴다.** 아직 초보라 AI가 안내하는 대로 따라가는
  경우가 많고, 뭘 이해했고 뭘 못했는지조차 모를 때가 많다. 그래서 질문을 던질 때
  구체적으로 어디서 막혔는지 같이 짚어가며 답을 유도한다 — 이 회고의 목적은 모르는
  지점을 정확히 찾아내서 공부할 거리로 만드는 것이다.
- **질문과 답을 짝지어, 같은 날 안에 나눠 쓴다.** 세션 중에 실제로 물었던 질문
  (예: "스킬 파일이 뭐야?")을 그대로 "아직 이해 못 한 부분"에 적는다. 그리고 그
  질문에 대해 그날 안에 스스로 이해하게 된 답을 "새로 알게 된 것"에 짝지어 적는다
  — 질문은 이해 못한 부분 쪽에, 그 답은 새로 알게 된 것 쪽에 나눠서 같은 날 안에
  완결한다. 끝까지 못 풀린 질문은 "새로 알게 된 것" 없이 "아직 이해 못 한 부분"에만
  남긴다.

## 3. 생성

```bash

```

생성 후 PR URL을 보고한다.
