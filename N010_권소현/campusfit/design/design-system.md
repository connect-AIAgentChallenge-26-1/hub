# 캠퍼스핏 디자인 시스템

`CampusFit Website (standalone).html`(Claude Design 레퍼런스)에서 추출한 규칙. 개발 단계(React)에서
이 문서 + `design-tokens.css` + [../기획서.md](../기획서.md)를 그대로 기준으로 삼는다.

2026-07-14: 레퍼런스가 새 버전으로 갱신되면서 `prototype.html`을 전면 재작업했다 — 상시 필터 패널 →
드롭다운 필터, 홈 카테고리 카드 그리드 → 리스트형, 카테고리 목록에 사이드바 내비게이션 추가, 그리고
가장 큰 변화로 **일반 공고에도 인앱 상세 화면이 생겼다** (아래 원칙 7 참고 — 예전 버전과 정반대 규칙).

**별도의 온보딩 화면이 없다.** 국립/사립 · 지역 · 학년 조건은 헤더 우측의 필터 버튼을 눌러야 열리는
드롭다운 패널에서 다루고, 콘텐츠 진입 전에 통과해야 하는 화면으로 만들지 않는다. 필터를 하나도 안
정해도 목록은 항상 바로 보인다.

**웹사이트다, 모바일 앱이 아니다.** 처음엔 380px 폰 카드 프레임으로 만들었다가 "너무 앱 같다"는
피드백을 받고 상단 네비게이션 + 넓은 페이지 레이아웃으로 다시 만들었다 (2026-07-09). 이후 화면을
추가할 때도 폰 프레임으로 되돌아가지 않는다.

## 색상 역할

| 토큰 | 역할 | 쓰는 곳 / 쓰지 않는 곳 |
|---|---|---|
| `--bulb` | 브랜드 primary (인디고) | 강조 버튼(팀원모집 관련), 선택된 필터 칩, 카테고리 tag 텍스트. 화면당 강조는 이 색 하나로 통일 |
| `--alert-soft` / `--alert-ink` | 마감 임박 전용 경고 | `D-3`처럼 7일 이내 마감에만 사용. 그 외 상황엔 쓰지 않는다 (색의 의미가 흐려짐) |
| `--card` | 은은한 강조 배경 | 팀원모집처럼 "다른 성격의 카드"를 표시할 때만 (`--bulb-soft`와 같은 값). 일반 카드엔 `--paper`/`--surface` |
| `--surface` | 옅은 중립 배경 | 비강조 버튼·필터 칩 기본 상태·hover 배경. `--paper`(순백)와 구분되는 한 단계 |
| `--ink / --ink-soft / --ink-faint` | 텍스트 위계 | 제목/본문/캡션 3단계로만 나눈다. 임의 회색 추가 금지 |

## 타이포 & 형태

- 폰트: Noto Sans KR (한글), 폴백 Pretendard → 시스템 산세리프
- 히어로 h1(홈): 46px / 800, letter-spacing -0.03em
- 페이지 h1(카테고리·상세): 30~34px / 800, letter-spacing -0.02em
- 섹션 라벨(h2): 15px / 700 — 큰 제목이 아니라 작은 소제목
- eyebrow 라벨(홈 상단): 12px / 600, letter-spacing 0.12em
- 본문: 15~16px, 캡션: 12~13px
- 버튼/입력 radius: 8px, 카드/정보박스: 12px, 썸네일/드롭다운: 16px, pill/칩: 999px
- 카드/옵션 테두리: `--line` 또는 `--line-strong`, hover 시 `--surface` 배경으로 전환 (그림자 없음, 드롭다운 패널만 예외적으로 그림자 사용)

## 레이아웃 구조 (웹사이트 셸)

- **상단 네비게이션(`.topnav`)**: 화면 전체 폭, `position: sticky`. 로고 + 실제 메뉴(홈/카테고리 5개/팀원모집)
  + 우측 필터 드롭다운 버튼. 모든 화면에서 항상 보임.
- **필터 드롭다운(`.filter-dd`)**: 헤더 버튼 또는 홈 히어로의 "필터 설정하고 보기" 버튼을 누르면 같은
  패널이 열린다 (체크박스 하나를 두 트리거가 공유). 국립/사립 · 지역 · 학년 세 항목이 칩 형태로 있고,
  선택 즉시 칩 색이 바뀐다. 패널 바깥을 클릭(스크림)하면 닫힌다.
- **컨테이너(`.shell`)**: `max-width: 1160px`, 중앙 정렬. 홈 화면 콘텐츠는 이 안에서 배치.
- **카테고리 목록(`.cat-layout`)**: 220px 사이드바(카테고리 5개 + 팀원모집 내비게이션) + 1fr 콘텐츠.
  860px 이하에서는 사이드바가 가로 스크롤 탭으로 접힌다.
- **상세형 화면(`.detail`)**: 리스팅 상세·팀원모집 게시판·게시글 상세·지원 완료처럼 읽는 화면은
  `max-width: 760px`로 좁혀서 가독성 확보.

## 컴포넌트 패턴

- **row**: 목록의 한 줄 (제목 + 보조텍스트 + 우측 D-day pill). 마감 임박, 카테고리 목록에 재사용
- **cat-row**: 홈 화면의 "카테고리별로 보기" 목록 한 줄 — 이름 + 한 줄 설명 + 건수 + 화살표(`→`).
  예전엔 카드 그리드였으나 레퍼런스를 따라 리스트형으로 바뀌었다
- **pill-alert / pill-neutral**: D-day 배지 — 7일 이내는 `pill-alert`(경고색), 그 외는 `pill-neutral`(중립색).
  같은 리스트 안에서도 항목별로 색이 갈린다
- **pill-team**: "팀원모집 N건" 배지. 리스트 행에서는 장식용이고(클릭 안 됨), 실제 이동은 리스팅
  상세 화면의 "팀원 모집하기" 버튼에서만 일어난다
- **post-card**: 팀원모집 게시글 목록 카드 — 클릭해서 상세로 들어감
- **btn-primary / btn-outline / btn-accent / btn-team**: 강조 4단계 — 기본 확정 행동(검은색 배경) /
  보조 행동(공식 페이지 확인, 아웃라인) / 팀원모집 확정 행동(댓글 지원하기, `--bulb` 배경) / 팀원모집
  유도 행동(리스팅 상세의 팀원 모집하기, `--bulb-soft` 배경)
- **info-box("한눈에 정리")**: 리스팅 상세 전용. 대상/지원내용/신청기간/신청방법 4행 표 — 공고 내용을
  훑어보기용으로 요약한다

## 원칙 (기획서에서 그대로 이어짐)

1. **조건에 안 맞는 정보는 애초에 안 보여준다** — 필터를 정하면 그 즉시 걸러진 목록만 보여준다. 조건을 안 정했다면 전체 목록을 보여준다.
2. **마감 임박은 항상 상단에, 항상 같은 pill 스타일로** — 홈 화면과 각 카테고리 목록 모두 마감일 오름차순으로 정렬해 놓치는 일이 없게 한다.
3. **팀원모집은 "다른 서비스"처럼 보이면 안 된다** — 같은 토큰만 쓰고, 구분은 `--card`(=`--bulb-soft`) 배경 하나로 충분히 한다.
4. **화면마다 강조색은 하나** — `--bulb`와 `--alert-soft`를 동시에 남발하지 않는다.
5. **카테고리 5개는 실제로 다른 화면·다른 데이터로 이어진다** — 진입점마다 결과가 같으면 안 된다.
6. **필터링은 "카테고리를 보여줄지"가 아니라 "카테고리 안 목록에" 적용된다** — 카테고리 내비게이션 자체는 항상 다 보인다. 조건(국립/사립·지역·학년)으로 걸러지는 건 그 안의 개별 공고 목록이다.
7. **지원 경로는 두 가지, 단 모든 공고가 상세 화면을 먼저 거친다** — (2026-07-14 변경, 이전 원칙과 반대)
   모든 공고는 클릭하면 인앱 리스팅 상세 화면("한눈에 정리" 표 + 공식 페이지 버튼)으로 먼저 들어간다.
   그 화면에서 실제 지원은 여전히 공식 페이지에서 이뤄진다 — 인앱 지원 폼을 새로 만드는 게 아니라,
   나가기 전에 조건을 한 번 더 확인시켜주는 중간 화면일 뿐이다. 팀원모집이 붙은 공고만 상세 화면에
   "팀원 모집하기" 버튼이 추가로 보이고, 눌러야 인앱 게시판(댓글 지원)으로 이어진다.
8. **넓은 화면에서 내용물이 빈 공간에 비해 너무 작으면 안 된다** — 화면을 넓힐 땐 타이포·카드 크기·콘텐츠 밀도를 같이 키운다. 홈 히어로 우측의 통계 컬럼처럼, 빈 공간을 의도적으로 콘텐츠로 채운다.

## 아직 안 만든 화면 (다음 디자인 세션에서)

- 사장님(운영자) 화면 없음 — 캠퍼스핏은 학생 전용 서비스라 해당 없음
- 지원 확정 후 게시글 상태 변화(예: "모집 마감" 뱃지)
- 마이페이지 (필터 조건 재설정은 헤더 드롭다운에서 항상 가능해서 별도 화면 불필요)
- "글쓰기"(팀원모집 새 글 작성) 폼 화면 — 현재 프로토타입은 버튼만 있고 실제 작성 화면은 없음
