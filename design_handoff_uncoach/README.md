# Handoff: 언코(Uncoach) — 화용 능력 코칭 AI 에이전트

## Overview
한국인 사회초년생·대학생이 한국어로 겪는 **격식·관계 화용(pragmatics)**을 진단하고 훈련시키는 글쓰기 코치. 문법이 아니라 "이 상황·이 관계에서 이 말이 적절한가"를 3축 루브릭으로 채점하고, **대신 써주지 않고** 스스로 다시 쓰게 만든다. "찾아와 훈련하는 헬스장" 모델(실시간 감시·개입 없음).

## About the Design Files
이 번들의 `언코 프로토타입.dc.html`는 **HTML로 만든 디자인 레퍼런스 프로토타입**이다 — 최종 룩앤필과 동작을 보여주는 것이 목적이며, 그대로 프로덕션에 복붙할 코드가 아니다. 작업 목표는 이 디자인을 **타깃 코드베이스의 기존 환경(React/Next, Vue, SwiftUI 등)에 그 패턴·라이브러리로 재구현**하는 것이다. 아직 환경이 없다면 프로젝트에 가장 적합한 프레임워크를 골라 구현한다(추천: React + TypeScript + Vite, 상태는 zustand/Context면 충분).

> 참고: 이 프로토타입은 자체 런타임(`support.js`, `.dc.html` 포맷)으로 동작한다. 이 런타임을 이식할 필요는 없다 — **화면·상태·로직 명세**만 참고해 대상 프레임워크로 다시 짜면 된다.

## Fidelity
**High-fidelity (hifi).** 색상·타이포·간격·인터랙션이 최종 의도값이다. 아래 디자인 토큰·컴포넌트 스펙을 그대로 재현할 것.

## ⚠️ 핵심: AI 채점 연동
프로토타입은 Gemini API로 채점한다(`gemini-2.5-flash` 기본, `gemini-2.5-pro` 옵션).

- 요청: `system_instruction` = 아래 "루브릭 시스템 프롬프트", `contents` = 상황 메타 + (있으면)지금까지의 대화 + 채점할 초안.
- `maxOutputTokens` 2048, `responseMimeType: application/json`. flash는 `thinkingBudget: 0`.
- 응답에서 첫 `{...}` 블록을 추출해 파싱하되, 모델이 넣는 트레일링 콤마·스마트 따옴표를 관대하게 처리한다(`parseLooseJson`).
- 견고화: 점수는 1~3으로 clamp, `deductions`는 초안에 실제 존재하는 구절만 통과, 파싱 실패 시 에러 상태로 폴백.
- 429(요청 한도)·5xx는 응답의 `RetryInfo.retryDelay`만큼 기다렸다가 최대 3회까지 자동 재시도한다. 대기가 5분을 넘으면(=하루 한도 소진) 재시도하지 않고 사용자에게 안내한다.

### 배포 시 API 키 처리
브라우저에 키를 박아 넣지 말 것. 두 가지 모드를 같은 코드가 자동으로 고른다.

**(A) 서버리스 프록시 — 권장.** 방문자가 키를 입력할 필요가 없다.
1. `api/gemini.mjs`를 프로젝트 루트에 둔 채로 Vercel에 배포한다(`api/`는 자동으로 함수가 된다).
2. 배포 환경변수에 `GEMINI_API_KEY`를 설정한다.
3. 프론트엔드는 별도 설정 없이 `/api/gemini`를 찾아 쓴다. 키는 서버에만 남는다.

**(B) 방문자가 자기 키를 입력 — 정적 호스팅.** GitHub Pages처럼 함수를 못 돌리는 곳, 또는 `file://` 로컬 실행.
- 프론트엔드가 `/api/gemini`에서 404(또는 JSON이 아닌 응답)를 받으면 자동으로 이 모드로 내려간다.
- 방문자는 **설정 화면**에서 자기 Gemini 키를 넣는다. 키는 그 브라우저의 `localStorage`에만 저장되고, `x-goog-api-key` 헤더로 전송된다(URL 쿼리에 실으면 리퍼러·중간 로그에 남기 때문).

`window.UNCOACH_PROXY_URL`을 지정하면 자동 판별을 덮어쓴다(`''`이면 항상 (B) 모드).

> 무료 티어는 분당·하루 요청 수 한도가 있다. (A) 모드에서 키 하나를 전체 방문자가 공유하면 금방 한도에 걸리므로, 트래픽이 있으면 유료 티어로 올리거나 (B) 모드를 쓸 것.

### 응답 JSON 스키마

## 3축 루브릭 (위계 순 — 병렬 아님)
가중치는 총점(100점) 계산에 쓰인다. `total = Σ (score/3) * weight`.

- **① 맥락·의도 (context) — 가중치 40.** 상대가 왜 이 상황에 있고 무엇을 기대·우려하는지 읽었는가. 최상위 축.
- **② 관계·격식 (register) — 가중치 30.** 호칭·존대·문체 레지스터가 관계에 맞는가. **과함(과공)도 부족도 모두 감점.**
- **③ 전략·표현 (strategy) — 가중치 30.** 완곡함·정보 배열·명료성.

**위계 원칙:** ①이 무너지면 ②③을 아무리 다듬어도 글 전체가 실패. → 피드백은 항상 **가장 낮은 축부터**(UI에서 "여기부터" 배지로 강조).

### 점수 척도 (3단계)
- `1` 위험(risk) — 관계·평판 실질 리스크 — 빨강
- `2` 무난(okay) — 목적은 전달되나 어색/막연 — 노랑
- `3` 적절(good) — 대부분의 상대에게 안전한 구간(최적 아님, 리스크 최소) — 초록

### 관계별 '적절'의 방향 (격식은 높을수록 좋은 게 아님)
- **교수**: 신중한 완충 + 오류 가능성 자기 귀속 + 요청 범위 특정. 과한 완충도 대체로 안전.
- **조교·행정**: 간결·정확 + 필요 정보(학번·과목·문항) 완비. 장황한 완충·아부는 감점.
- **동료(조원)**: 가볍고 명확한 톤이 3점. 교수식 과공·과격식은 거리감 → 1~2점.

## Screens / Views
사이드바(고정 228px, 딥네이비 `--side`) + 우측 메인. 6개 화면.

### 1. 온보딩 (isOnboarding)
- 중앙 정렬, 640px. 배지 + 큰 헤드라인 + 서브카피 → 카드.
- **1단계 역할 선택**(3열 그리드 카드): 대학생 / 대학원생 / 취준생 / 사회초년생 / 프리랜서·자영업 / 경력·이직. 각 카드에 title + desc.
- **2단계 목표 칩**(pill 토글): 교수·조교 메일 격식 / 팀플 소통 / 사회 격식 전반.
- 둘 다 선택돼야 "훈련 시작하기" 활성. 하단 프라이버시 안내.

### 2. 홈 대시보드 (isHome)
- 헤더 + 3열 축 카드(각 축: 게이지 바 + 레벨 칩 + "첫 세션 대비 ±n" 추세; 가장 낮은 축엔 "집중 축" 배지).
- 하단 2열: (좌, 네이비 카드)오늘의 추천 훈련 = 가장 낮은 축을 정면 훈련하는 상황 자동 추천 + "바로 시작"/"다른 상황 고르기". (우)최근 세션 리스트 = 날짜·제목·축칩(①n②n③n)·총점.

### 3. 상황 선택 (isPicker)
- 관계별 그룹(교수 / 조교·행정 / 동료(조원)), 각 그룹 헤더에 관계 힌트.
- 그룹 안 2열 카드: 제목 + "핵심 ①/②/③" 배지 + 긴장 설명. 클릭 → 훈련 루프.

### 4. 훈련 루프 (isTrain) — 핵심 화면
- 상단: "← 상황 다시 고르기" + 상황 제목 + 관계 칩.
- 2열. **좌**: 상황 브리핑(상대/목적/긴장 + "이 관계에서 '적절'의 방향" 강조 박스) → 초안 작성 textarea + "화용 채점 받기"/"예시 초안 넣기" + 글자수.
- **우**: 채점 전=루브릭 3축 안내(위계 설명). 채점 중=스피너("맥락→격식→전략"). 결과=아래.
- **채점 결과 카드**: 큰 총점 "57 / 100점" + 직전 대비 델타 칩 + "위계 가중 총점 — 맥락 40·격식 30·전략 30" 캡션. 3축 행(각 축: 이름·레벨칩·게이지·근거문장; 가장 낮은 축은 빨강 테두리+"여기부터" 배지, 재시도 시 ▲/▼ 델타).
- **감점 포인트 카드**("어디서 깎였나"): deductions를 축라벨 태그 + 인용 구절(빨강 하이라이트) + 이유로 나열.
- **코치 카드**(accent-soft): 코칭 멘트 + "딱 하나만 바꿔보세요" fix 박스 + 액션(다시 써보기 / 자산집에 저장 / 세션 마치기). 3축 모두 적절이면 축하 배너 + 저장 유도.

### 5. 궤적 (isProgress)
- 축별 그룹 막대 차트(세션별 3막대: context=accent, register=good, strategy=warn) + 범례.
- 하단 3열 요약: 각 축 현재 레벨 + "첫 세션 대비 ±n".

### 6. 표현 자산집 (isAssets)
- 스스로 완성한 좋은 표현만 저장(왼쪽 초록 보더 카드): 인용문 + 상황 태그 + 날짜. "대신 써준 문장은 여기 없음" 원칙.

## Interactions & Behavior
- 네비게이션은 `screen` 상태 스위치(온보딩 완료 전엔 사이드바 숨김).
- "예시 초안 넣기" → 해당 상황의 seed 초안 주입(데모용).
- 채점: 로딩 상태(스피너) → 결과. 실패 시 인라인 에러 + write 단계 복귀.
- "다시 써보기" → 같은 초안 유지한 채 write 단계, 재채점 시 직전 시도 대비 델타 표시.
- "세션 마치기" → 마지막 점수를 history에 append, 토스트, 홈 이동.
- "자산집에 저장" → bestSentence(또는 초안) 저장, 토스트.
- 토스트: 하단 중앙 pill, 2.4s 후 사라짐.
- 지속성: profile/history/assets를 localStorage(`uncoach-...`)에 저장·복원.

## State Management
- `screen`: onboarding|home|picker|train|progress|assets
- `obRole`, `obGoal`(온보딩 선택), `profile`(확정)
- `situationId`, `draft`, `phase`(write|scoring|result), `attempts[]`(각 시도의 점수·근거·감점·코치·fix·best)
- `history[]`(세션 기록), `assets[]`(저장 표현), `toast`
- 데이터 페칭: 채점 시 Anthropic API 1회.

세이지 그린: accent `#3d7d5f`, side `#1e3328`, bg `#f5f7f3` … (프로토타입 THEMES 참고).
잉크 미니멀: accent `#2c3e50`, side `#191918`, bg `#f7f6f3` … (동).

레벨색: 위험=bad, 무난=warn, 적절=good.

### 타이포
- 폰트: **Pretendard Variable**(fallback: -apple-system, Noto Sans KR, Malgun Gothic).
- 스케일: 페이지 h1 26px/800, 온보딩 헤드라인 34px/800, 총점 36px/800, 카드 제목 13~15px/700, 본문 13~14px/1.6~1.75, 캡션 11~12px. letter-spacing 제목 -0.01~-0.02em. 한국어 줄바꿈: `word-break:keep-all`.

### 기타
- radius: 카드 14px, 버튼/인풋 10~11px, pill 999px.
- shadow: 카드 `0 1px 4px rgba(20,40,60,0.05)`, hover `0 2px 10px rgba(30,60,90,0.08)`.
- 게이지 바 높이 7~8px, `background: level color`, `width = score/3*100%`, transition 0.4s.
