# 지금리뷰 3주차 발표 대본

발표 시간은 라이브 데모 포함 약 9~11분을 기준으로 작성했습니다.

## 1. 표지

안녕하세요. 지도 기반 리뷰 서비스 **지금리뷰**의 3주차 진행 상황을 발표하겠습니다. 지금리뷰는 지도에서 식당이나 카페를 찾고, 업체 정보를 확인하고, 리뷰를 작성한 뒤 그 내용을 AI가 다섯 단계로 분석해 보여주는 서비스입니다. 오늘은 처음 어떤 문제에서 출발했는지, 3주 동안 무엇을 만들었는지, 현재 기술 구조와 실제 데모 순서까지 말씀드리겠습니다.

## 2. 문제 정의

저희가 처음 주목한 문제는 리뷰가 부족한 것이 아니라, 리뷰가 많아도 믿고 선택하기 어렵다는 점이었습니다. 기존 서비스에서는 작성자가 실제로 방문했는지 바로 판단하기 어렵고, 리뷰가 많이 쌓이면 전체 분위기를 빠르게 파악하기도 어렵습니다. 그래서 지금리뷰는 영수증으로 방문 근거를 확인하고, 작성된 텍스트를 한눈에 이해할 수 있게 정리하는 방향을 잡았습니다.

## 3. 제품 흐름

사용자 흐름은 네 단계로 단순하게 구성했습니다. 먼저 현재 보고 있는 지도 주변에서 장소를 검색합니다. 업체를 선택하면 상세 정보와 리뷰를 확인합니다. 검색은 로그인하지 않아도 가능하지만, 리뷰를 작성할 때는 로그인을 요청합니다. 작성된 리뷰는 별점을 받는 대신 AI가 매우 좋음부터 매우 아쉬움까지 다섯 단계 중 하나로 분류하고, 전체 결과를 막대그래프로 보여줍니다.

## 4. 1주차

1주차에는 바로 코드를 많이 작성하기보다 기준을 정하는 데 집중했습니다. 서비스가 해결할 문제와 핵심 사용자 가치를 정리했고, 영수증 결제일은 작성일 기준 30일 이내로 인정하는 규칙, 이미지 해시와 승인번호로 중복 사용을 막는 구조, 좋아요 가중치를 90일 동안 적용하는 구조를 설계했습니다. React와 Express, Supabase를 사용하는 개발 구조와 모바일 우선 디자인 시스템도 이때 정했습니다.

## 5. 2주차

2주차에는 예시 화면을 실제 서비스 흐름으로 바꾸었습니다. Kakao Maps JavaScript SDK와 Local REST API를 연결해 실제 식당과 카페를 검색할 수 있게 했습니다. 검색할 때 지도가 갑자기 다른 지역으로 이동하지 않도록 현재 지도 주변 결과를 우선하고, 상세 화면에 들어갔다가 돌아와도 검색어와 결과, 지도 위치가 유지되게 했습니다. 자동완성, 홈 초기화, 로그인과 리뷰 작성 진입 흐름도 이 시기에 연결했습니다.

## 6. 3주차

3주차에는 데이터베이스와 AI 분석을 붙였습니다. Supabase에 사용자 프로필, 업체, 영수증, 리뷰, 좋아요 테이블과 검증 규칙을 준비했습니다. OpenAI Responses API를 Express 서버에서 호출해 리뷰를 다섯 단계로 분류하고, 신뢰도와 핵심 키워드도 구조화된 형태로 받도록 했습니다. 현재 프론트 테스트 5개와 서버 테스트 3개가 있으며, 모바일 홈과 리뷰 화면, 마이페이지도 같은 흐름으로 정리했습니다.

## 7. 현재 화면

이 화면이 현재 localhost에서 동작하는 실제 결과입니다. PC에서는 왼쪽 목록과 지도를 함께 사용하고, 모바일에서는 지도를 최대한 넓게 보여주면서 검색과 필터, 하단 탐색을 배치했습니다. 같은 기능을 억지로 축소한 것이 아니라, 사용 환경에 따라 탐색 방식이 자연스럽게 바뀌도록 구성했습니다.

## 8. 기술 스택과 구조

프론트엔드는 Create React App 기반 React로 만들었고, 지도 UI와 화면 이동, 반응형 화면을 담당합니다. Express 서버는 장소 검색을 중계하고 입력값을 검증하며, OpenAI 요청과 비밀 키를 브라우저 밖에서 관리합니다. Supabase는 로그인과 Postgres 데이터베이스를 담당합니다. 지도와 장소 검색은 현재 Kakao API로 동작합니다. 이처럼 브라우저, API 서버, 외부 API, 데이터베이스의 역할을 분리해 이후 OCR이나 배포 기능을 추가하기 쉽게 만들었습니다.

## 9. AI 리뷰 분석

AI 분석 과정은 단순합니다. 사용자가 리뷰를 입력하면 서버에서 길이와 형식을 먼저 확인합니다. 그다음 GPT-5.6 Luna 모델에 다섯 단계 중 하나만 선택하도록 요청하고, label, confidence, keywords 형태의 정해진 JSON으로 결과를 받습니다. 프론트는 이 결과를 막대그래프에 반영합니다. 별점을 직접 선택하게 하지 않는 이유는, 사용자가 작성한 실제 문장의 의미를 서비스가 일관된 기준으로 정리하는 경험을 확인하고 싶었기 때문입니다.

## 10. 라이브 데모

이제 실제 화면을 보여드리겠습니다.

먼저 홈 버튼을 눌러 검색창이 초기화되고 지도가 현재 위치로 돌아오는 모습을 보여드리겠습니다. 다음으로 식당이나 카페 이름을 입력해 자동완성과 현재 지도 주변 검색 결과를 확인하겠습니다. 결과 탭을 누르면 업체 상세 화면으로 이동하고, 다시 지도로 돌아와도 이전 검색 상태가 유지됩니다. 리뷰 작성은 로그인이 필요한 흐름을 보여드린 뒤, 테스트 리뷰를 입력해 AI 분석 결과가 다섯 단계 그래프에 반영되는 모습과 마이페이지에서 작성 내용을 확인하는 것까지 보여드리겠습니다.

데모 중 네트워크가 늦을 경우에는 새로고침하지 않고 잠시 기다린 뒤 다시 검색하겠습니다. 지도 검색은 외부 API 상태의 영향을 받을 수 있습니다.

## 11. 현재 상태와 다음 단계

현재 실제로 동작하는 것은 지도와 장소 검색, 자동완성, 로그인과 세션, 텍스트 리뷰 AI 분석, 모바일 반응형 화면입니다. 다만 오늘 AI 분석 데모에서는 흐름을 먼저 검증하기 위해 영수증 인증을 우회한 테스트 리뷰를 사용합니다. 다음 단계에서는 영수증 이미지를 Supabase Storage에 저장하고, CLOVA OCR로 상호명과 결제일을 검증한 뒤, 인증을 통과한 리뷰만 실제 데이터베이스 집계에 포함할 예정입니다. 이미지 해시와 승인번호를 이용한 중복 차단도 이 과정에서 연결합니다.

## 12. 마무리

정리하면 지금리뷰는 리뷰의 양보다 방문 근거와 해석을 먼저 보여주는 서비스입니다. 3주 동안 기획 문서에서 출발해 실제 지도 탐색, 사용자 흐름, 데이터 구조, AI 분석까지 이어지는 MVP를 만들었습니다. 오늘은 다섯 단계 표현이 직관적인지, 인증 리뷰 표시를 어느 화면에서 가장 강하게 보여줘야 하는지, 실제 장소 선택에 빠진 정보가 무엇인지 피드백을 받고 싶습니다. 감사합니다.

## 발표 직전 체크

- 터미널에서 프론트엔드와 Express 서버가 모두 실행 중인지 확인
- `http://localhost:3000`에서 지도와 장소 검색 확인
- 로그인할 테스트 계정 준비
- 분석에 사용할 리뷰 문장을 메모장에 미리 복사
- 데모 실패에 대비해 PPT 7번 슬라이드의 실제 화면 캡처 활용
