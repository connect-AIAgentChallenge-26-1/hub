## what is leadership?

Source: https://velog.io/@gyutaetae/what-is-leadership

> recently, i deeply thinking about what true leadership really means. i came across a deeply inspiring quote from jensen, the ceo of nvidia.
today, i'd like to share his leadership philosophy and how it shapes the unique corporate culture of silicon valley

![]
(https://velog.velcdn.com/images/gyutaetae/post/a8df01d8-035f-4943-9ac7-90167a857019/image.png)

## 1. flat and  transparent organization
First, Jensen emphasizes a flat and transparent culture. In Nvidia, info-distortion is minimized because he has dozens of direct reports. He believes that grat leaders control. instead, they transparently share context and information so that team members can make the right decisions on their own. this is why tech companies value autonoy over authority.

![](https://velog.velcdn.com/images/gyutaetae/post/9231f4c9-07c1-4635-b06b-fdd37b34f572/image.png)

my expereince:
in a university database class, i led a project developing an ai=assisted tax reporting system. because my team maintained a flat, peer to peer relationship, we can be open and without hesitatinon bring up a critical flaw: "we cannot rely on ai, we need a human-in-the-loop verification process". becuase of our flat culture we skipped unnecessary office politics, cut down communication time, and fully focused on the project. by adding that verification step, we successfully built a system that was both fast through ai and completely accurate throuh human.

## 2. survival strategy in sillicon valley's war for talent
Second, Top tier engineers don't move just for high salaries. they want a place where they can fully unleash their potential and create technologies that the world has never seen before. leaders must provide an ecosystem where engineers feel they can achieve their **life's work**. if we want to be hired by these companies, we should also look for places that offer this kind of growth.

my thought
to be honest before watching this interview, i was only focused on superficial things. i used to think about how big a company was or how high the salary would be.
i must look for a company where i can build my  on life's work. i realized that when i join an ecosystem with a great leader who empowers their team, i can truly maximize my potential and achieve both personal growth and corporate success simultaneously

## 3. practicing servant leadership
서번트리더십 : 리더가 권력을 행사하기보다 구성원의 성장과 복지를 최우선으로 돕는 리더십 철학.
![](https://velog.velcdn.com/images/gyutaetae/post/dcc10fda-56bb-49b6-a613-97ecd4538cfa/image.png)

Finally, learders exist not to rule over employees, but to support them. this is deeply rooted in the philosophy of **empowerment(권한 위임)**. when a leader creates the right environment and conditions, employees naturally become self-motivated. they proactively immerse themselves in their work, ultimately aligning personal dreams with corporate growth.

훌륭한 리더란

## conclusion
as members of a silicon valley, understanding this cultural mindset is just as important as building our technical skills. when we prepare for interview, let's show them that we are not just lokking for a job, but looking for a place to build our life's work. thank you.

## week2. silicon valley

Source: https://velog.io/@gyutaetae/week2.-silicon-valley

> if there is something ai could not replace at workplace, what would it be?

## accountability
tech world has been changing ever more rapidly. employees are expected to not only participate in automaion, but also build scalable pipelines.
Yet it is crtical to fully comprehend the logic and basics behind it. because in that 1% margin of error, humans are accontable, not ai. the ability to use a variety of ai tools detect the errors validate and scale them. that is what tech looking for regardless of the specific functions of an org.

## 1. what is better thing you can do than ai?

What sets me apart from AI is the capacity for  accountability. No matter how advanced AI becomes, it cannot legally or ethically take responsibility when things go wrong. In that 1% margin of error, it is a human who must step up.

second thing is human intuition and the ability to connect hidden dots. No matter how advanced AI becomes, it only analyzes existing data patterns. It cannot truly understand human emotional nuance or the 'why' behind user behavior.

In critical decision-making, I rely on contextual empathy to understand what users truly want, revealing insights that algorithms miss. Combined with my sense of accountability, I don't just validate AI outputs for errors—I guide them to deliver real, human-centric business impact.

## 2. Tell me about a time when you improved a process or driving efficiency for your team.
During a 24-hour school hackathon, I served as the Backend Lead to ship an MVP. To balance speed and quality, I focused on eliminating setup friction.

Before the clock started, I chose TypeScript to ensure code quality and prevent runtime errors. Then, I built a standardized boilerplate with all necessary libraries and distributed it via GitHub.

By alignment of the development environment upfront, we saved hours of configuration and communication. This allowed the team to spend the entire 24 hours purely on core feature development, successfully shipping a stable MVP on time.

기존 방식: 영수증 수집 -> 엑셀 입력 -> 카테고리 분류 -> 세무사 전달 (최소 1~2시간).
우리 방식: 사진 찰칵(3초) -> AI 에이전트가 자동 분류 및 장부 기입(10초) -> 세금 신고 알림(즉시). 시간 단축 100배.

- 타겟층:
핵심: 1인 자영업자, 카페/식당 운영자, 3.3% 프리랜서.

- 차별점 (기존 서비스 vs 우리 에이전트):
기존 서비스(가계부/핀테크 앱): 사용자가 일일이 확인하고, 누락된 건 수정해야 함 (수동적).
우리 에이전트(TaxPilot):
행동하는 AI: 단순히 기록하는 게 아니라, API를 통해 '세무 신고 플랫폼'에 데이터를 전송하거나 **'누락된 경비 리포트'**를 생성합니다.
맥락 파악: 단순히 '식대'라고 분류하는 게 아니라, '거래처 사람과 식사'인지 '개인 식사'인지 대화로 물어보고 적절한 항목으로 처리합니다.

## 배우담 개발일지1

Source: https://velog.io/@gyutaetae/%EB%B0%B0%EC%9A%B0%EB%8B%B4-%EA%B0%9C%EB%B0%9C%EC%9D%BC%EC%A7%801

## 배우담은 노년층을 위한 화면 길잡이 접근성 도구

개발시작 전

### 1. 작동흐름
사용자가 배우담 앱을 백그라운드에서 켠다. 카톡을 켰을때 어딜눌러야할지 시니어가 모르면 음성으로 "배우담아 아들에게 메세지 보내려면 어떻게해야해?" 라고하면 아들에게 프로필로 들어가는 방법을 스와이프나 터치를 하도록 앱위에 오버레이를 띄워서 유도해준다. 화면을 터치를 할때는 해당버튼만 남기고 나머지화면을 모두 하얗게 만들어서 가장 사용하기 쉽고 직관적으로 터치를 유도한다.

### 2. 면책조항
송금앱 같은 부분에서 잘못 실수를 해서 잘못 송금을 할 수도있으니까 면책조항을 추가한다. 앱을 시작할때 배우담을 실수를 할 수 있습니다.를 추가한다.

### 3. 구현디테일
kotlin을써서 android 네이티브 앱
데이터는 로컬에만 저장하고
최대한 구현이 쉬운기술을 선택해서 에러가 적게 생기고 빨리완성해서 mvp를 제작하는것을 목표로한다.

### 3. 제약조건
서버, 데이터베이스를 사용하지않는다. 로컬에서 저장한다.
계좌번호나 카드번호같은 금융관련된 개인정보를 이앱을사용하면서 입력하면 깨름직할수있기 때문에 로컬에서 저장하는것을 제약조건으로 둔다.

로그인을 구현하지않는다. 로그인조차도 처음에 노인들이 어려울수있기때문에 접근성을 위해 로그인을 구현하지않음
부가 스크린을 만들지 않는다. 화면과 UI요소는 적을수록 좋다.

포인트 색상한가지만 제외하고 전부 무채색을 사용한다. 주 타겟층인 노인들을위한 간결한색상선택

모든앱에서 이앱이 작동가능해야야한다. 금융 쇼핑 증권앱등등
추후에는 안드로이드 os에서도 가이드가 가능해서 화면밝기 낮추는법, 카메라 앱 켜는 법 이런것도 가능하게 할 것이다.

### 4. 완료기준
핵심 작동흐름이 정상 작동한다.
사용자가 배우담이라는 트리거를 말하고 요구사항을 말한다음 다른 화면을 마스킹해서 버튼사용을 유도하기까지 초내로 작동한다.
정확히 사용자가 원하는 의도대로 그 버튼만 남기고 나머지 화면을 하얗게 만든다

해결 : 1차검증
타깃 앱 : 카카오톡, 쇼핑앱, 교통예매앱
배우담 코어엔진과 오버레이를 먼저만들고 테스트용 앱화면으로 접근성 노드 탐색/버튼 강조/1초 반응을 증명한후
실기기 후 검증: 실제 카톡, 쇼핑앱, 교통예매앱에서 접근성 노드가 얼마나 잘읽히는지 성공률 측정.

모든 앱에서 100%작동이 아니라 지원가능한 화면에서 다음에 누를 버튼을 선명하게 안내로 모든 앱에서 작동할 수 없다는것을 사용자에게 솔직하게 알림

문자 쇼핑 교통예매앱을 적황한 실제 앱을 정해야함
카카오톡 쿠팡 코레일톡으로 정함
이유: 사용 빈도와 노년층 니즈가 크고 메세지 보내기 / 상품 구매흐름 / 기차 예매 흐름으로 서로다른 UI 패턴을 검증할 수 있음

## UX리서치
노인이 실제 상황에서 겁먹지 않고 끝까지 따라갈 수 있는 한장면 상상

유즈 케이스: 사용자는 카카오톡/쿠팡/코레일톡에서 뭘눌러야할지 몰라 멈춘다. 배우담은 사용자의 말을 들어 현재 화면을 읽는다. 화면대부분을 하얗게 덮고 다음 버튼만 남긴다. 사용자는 자기손으로 버튼을 누른다.

### 1. 배우담은 언제 켜져있어야하나?
노인들은 백그라운드 앱을 추상적으로 이해하기 어려움
페이스북 메신저 앱처럼 화면모서리에 둥둥떠다니는 UI를 추가해서 백그라운드에서 실행되고있다는것을 직관적으로 보여줌

처음에는 배우담앱에서 사용자가 원하는 바를 말하고 실제앱으로 넘어가서 가이드를 받는 방식이었으나 화면전환에 익숙하지않은 노인들을 위해 실제 앱위에서 모든 것을 처리하는것으로 결정
### 2. 마스킹 화면은 전부 하얗게할까?
완전흰색보다 거의흰색 + 목표 버튼 주변만 또렸하게 남겨야겠다. 완전 흰색은 휴대폰이 고장났다고 느낄 수있어야한다.

화면을 스와이프하는것이 필요할때는 짧은 문구를 추가한다.
그리고 흰색 화면이 되었을때 언제든지 빠져나갈수있게 왼쪽위에 화살표를 추가해서 빠져나갈수있게해준다.

### 3. 버튼을 찾지 못햇을때는 어떻게할까?
버튼을 확신하지하면 아무것도 강조하지않는다 이것이 배우담의 신뢰를 지키는 핵심 원칙이다.
지금 화면에서는 버튼을 찾지 못했어요라는 문구를 띄운다

### 4. 작업이 끝났다는 걸 어떻게 아나?
코레일톡에서 조회하기를 누른 뒤 다음화면으로 넘어가면서 배우담이 계속 이전명령을 들고있으면 위험하다. 버튼을 한번 안내한뒤 자동으로 일시정지 상태로 돌아가도록해서 다시 도움을 요청해야 다음 안내를 시작한다.

### 5. 음성인식 실해 fallback
동그라미가 살짝 커지면서  "다시말하기", "이버튼 찾아줘" 같은 버튼을 보여준다 마지막 수단으로 짧은 텍스트 입력을 둡니다.
앱전환없이 동그라미를 최대한 활용하기

### 6. 듣는 중 상태
노인들은 말속도가 느려서 말한다음 다음문장까지 간격이 길수있다 그래서 사용자가 말하기 시작하면 말이 끝난 뒤 약 1.5초를 기다리게한다. 듣는 상태는 20초으로 해서 말속도가 느린 노인들을 위해 시간을 넉넉히주었다.

### 7. 대기시간
마스킹이 된 상태에서 버튼을 누르지 않고 10초동안 무동작하면 마스킹을 해제하고 동그라미상태로 다시돌아온다.
노인들을 위해 10초라는 넉넉한 시간을 주었고 뒤로 빠져나가기를 못볼수도있으니 10초뒤에는 자동으로 빠져나오게해준다.

### 8. 자동 연속안내
버튼을 눌러서 다음 화면으로 넘어갔을때 다시 음성을 입력하고 버튼을 누르는것은 번거로움 앞의 사용자의 요청을 기억해서 그다음 화면에서도 그 맥락에 맞는 추천 버튼을 계속해서 자동으로 안내해준다 이 화면은 2초 잇내에 분석되지 않으면 종료된다. 최대 5단계연속으로 자동 분석이가능하다
무제한으로 계속따라가면 사용자가 통제감을 잃고 잘못된 흐름으로 들어갔을때 위험함

# GNU 14th Backend Hackathon Template

경상국립대학교 14기 백엔드팀을 위한 24시간 해커톤 스타터 템플릿입니다.

이 저장소의 목적은 하나입니다. 해커톤 당일에 환경 구축, 인증 세팅, API 라우팅, DB 연결, 폴더 구조 결정에 시간을 쓰지 않고 팀이 바로 핵심 기능 개발에 들어가게 만드는 것입니다.

백엔드팀 리더로서 반복되는 초기 세팅을 미리 정리해 두었고, 팀원들은 이 템플릿을 기준으로 필요한 도메인만 바꿔서 개발을 시작하면 됩니다.

## 왜 만들었나요?

해커톤은 시간이 짧습니다. 특히 24시간 해커톤에서는 기술 선택보다 구현 속도와 팀 합의가 더 중요합니다.

매번 새 프로젝트를 만들 때마다 다음 작업에 시간이 빠집니다.

- 프로젝트 생성과 폴더 구조 결정
- 인증 방식 선택
- API 라우팅 방식 결정
- 데이터베이스 연결
- ORM 설정
- 요청값 검증
- 프론트엔드와 백엔드 연결 방식 합의
- 배포 가능한 Next.js 구조 정리

이 템플릿은 위 작업을 미리 끝내 두어, 팀이 문제 정의와 기능 구현에 더 많은 시간을 쓸 수 있게 합니다.

## 해커톤에서 좋은 이유

### 1. 바로 개발을 시작할 수 있습니다

Next.js, API 라우팅, Supabase 인증, Drizzle ORM, PostgreSQL 연결 구조가 이미 준비되어 있습니다. 팀원은 프로젝트 구조를 새로 설계하지 않고, 주어진 예시를 자기 서비스 도메인에 맞게 바꾸면 됩니다.

### 2. 프론트엔드와 백엔드 연결이 단순합니다

Hono 기반 API와 타입 추론 가능한 클라이언트 구조를 사용합니다. 프론트엔드에서 서버 API를 호출하는 흐름이 명확해서, 짧은 시간 안에 팀원 간 역할 분담이 쉽습니다.

### 3. 인증과 DB를 처음부터 고려합니다

대부분의 서비스는 로그인, 사용자 정보, 데이터 저장이 필요합니다. 이 템플릿은 Supabase Auth와 Drizzle ORM 기반 DB 구조를 포함하고 있어, 나중에 급하게 붙이는 방식보다 안정적으로 기능을 확장할 수 있습니다.

### 4. 검증과 유지보수 비용을 줄입니다

Zod와 React Hook Form을 사용해 입력값 검증 흐름을 잡아 두었습니다. 해커톤 후반에 자주 발생하는 "값이 이상하게 들어와서 터지는 문제"를 줄일 수 있습니다.

### 5. 발표 가능한 화면까지 빠르게 만들 수 있습니다

Tailwind CSS, shadcn/ui 계열 컴포넌트, lucide-react 아이콘을 기반으로 기본 UI를 빠르게 구성할 수 있습니다. 백엔드 기능만 만든 뒤 화면이 없어 보여주지 못하는 상황을 줄이는 데 도움이 됩니다.

## 기술 스택

| 영역 | 사용 기술 | 선정 이유 |
| --- | --- | --- |
| Framework | Next.js 16 App Router | 프론트엔드, API Route, 배포 구조를 하나의 프로젝트에서 관리할 수 있어 해커톤에 적합합니다. |
| Language | TypeScript | API 응답, 폼 데이터, DB 모델을 타입으로 관리해 짧은 시간 안에 실수를 줄입니다. |
| Runtime / Package Manager | Bun | 설치와 실행 속도가 빠르고, 해커톤 환경에서 초기 대기 시간을 줄일 수 있습니다. |
| API Server | Hono | 가볍고 빠르며 라우팅 구조가 명확합니다. Next.js API Route 안에서 백엔드 엔드포인트를 깔끔하게 구성할 수 있습니다. |
| API Client | hono/client | 서버 라우트 타입을 프론트엔드에서 활용할 수 있어 API 계약을 맞추기 쉽습니다. |
| Authentication | Supabase Auth | 이메일 인증, 세션 관리, 서버/클라이언트 연동을 빠르게 붙일 수 있습니다. |
| Database | PostgreSQL | 실제 서비스 확장까지 고려할 수 있는 범용 RDB입니다. Supabase와 조합하기 좋습니다. |
| ORM | Drizzle ORM | 스키마를 TypeScript 코드로 관리할 수 있고, SQL에 가까운 방식이라 백엔드 학습에도 좋습니다. |
| Validation | Zod | API 요청값과 폼 입력값을 같은 방식으로 검증할 수 있습니다. |
| Form | React Hook Form | 폼 상태 관리가 가볍고, Zod와 결합하기 쉽습니다. |
| Server State | TanStack Query | API 데이터 로딩, 캐싱, 로딩/에러 상태 처리를 빠르게 구현할 수 있습니다. |
| Styling | Tailwind CSS 4 | 빠르게 UI를 만들고 수정하기 좋습니다. 팀원 간 CSS 충돌도 줄일 수 있습니다. |
| UI | shadcn/ui, Base UI, lucide-react | 기본 컴포넌트와 아이콘을 빠르게 조합해 발표 가능한 화면을 만들 수 있습니다. |

## 현재 포함된 기능

- Next.js App Router 기반 프로젝트 구조
- Hono 기반 API 라우트 예시
- `/api/hello` 기본 API
- `/api/tasks` CRUD 예시
- Zod 기반 요청값 검증
- Supabase 클라이언트/서버 클라이언트 분리
- Supabase Auth 회원가입 예시
- Middleware 기반 세션 갱신 구조
- Drizzle ORM PostgreSQL 스키마 예시
- 사용자, 게시물, 댓글, 좋아요, 팔로우 테이블 예시
- TanStack Query 기반 API 호출 예시
- Tailwind CSS 기반 기본 UI

## 프로젝트 구조

```txt
app/
  api/[[...route]]/route.ts   # Hono API 엔드포인트
  page.tsx                    # 메인 예시 화면
  signup/page.tsx             # Supabase 회원가입 예시
  tasks/page.tsx              # API 데이터 호출 예시
  profile/page.tsx            # 인증 사용자 확인 예시
drizzle/
  schema.ts                   # Drizzle DB 스키마
  index.ts                    # DB 클라이언트
lib/
  api.ts                      # Hono 타입 클라이언트
  auth-context.tsx            # 클라이언트 인증 컨텍스트
  queries.ts                  # TanStack Query 예시
  supabase/                   # Supabase client/server 헬퍼
```

## 실행 방법

### 1. 의존성 설치

```bash
bun install
```

### 2. 환경 변수 설정

루트에 `.env.local` 파일을 만들고 필요한 값을 채웁니다.

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
DATABASE_URL=
OPENAI_API_KEY=
```

현재 템플릿에는 Supabase Auth, Drizzle/PostgreSQL, AI SDK 의존성이 포함되어 있습니다. 사용하지 않는 기능은 해커톤 주제에 맞게 제거해도 됩니다.

### 3. 개발 서버 실행

```bash
bun dev
```

기본 주소는 다음과 같습니다.

```txt
http://localhost:3000
```

## DB 명령어

```bash
# Drizzle migration 파일 생성
bun run db:generate

# migration 실행
bun run db:migrate

# 현재 스키마를 DB에 바로 반영
bun run db:push

# Drizzle Studio 실행
bun run db:studio
```

해커톤 중에는 빠른 검증이 필요하면 `db:push`를 사용하고, 최종 정리 단계에서는 migration 파일을 남기는 방식을 추천합니다.

## 팀 사용 방법

1. 이 저장소를 fork하거나 template으로 복사합니다.
2. 서비스 이름과 메인 화면을 팀 주제에 맞게 변경합니다.
3. `drizzle/schema.ts`에서 필요한 테이블을 정의합니다.
4. `app/api/[[...route]]/route.ts`에 필요한 API를 추가합니다.
5. `lib/queries.ts` 또는 Hono client를 통해 프론트엔드와 연결합니다.
6. 발표에 필요한 핵심 플로우부터 구현합니다.
