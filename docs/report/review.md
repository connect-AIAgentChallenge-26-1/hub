# 보고서 점검 지시서 — docs/report/ 리뷰·피드백 절차

이 문서는 docs/report/의 작업 보고를 **다른 LLM이 교차 점검**할 때와, 그 리뷰 피드백을 **구현 agent가 반영**할 때의 절차서다. 제품 범위·계약·완료 조건의 진실 소스는 [instructions.md](../instructions.md)의 문서 지도를 따르며, 이 문서는 보고서를 "어떻게 점검하고 어디에 기록할지"만 정의한다.

사용법: 리뷰 세션에서 `docs/report/review.md 절차에 따라 미체크 보고를 점검해줘`라고 지시한다.

## 파일과 점검 방향

| 파일 | 작성자 | 점검자 | 점검 절차 |
|---|---|---|---|
| [report_claude.md](report_claude.md) | 구현 세션 (Claude) | 리뷰 LLM (GPT 등) | 아래 A절 |
| [report_gpt.md](report_gpt.md) | 리뷰 세션 (GPT 등) | 구현 agent (Claude) | 아래 B절 |

## 공통 규칙

1. 두 파일 모두 append-only다. **유일한 허용 수정**: 점검을 마친 항목의 `- 확인: [ ]`를 `- 확인: [x] YYYY-MM-DD HH:MM 점검자`로 바꾸는 한 줄이다. 그 외 기존 내용은 절대 수정·삭제하지 않는다.
2. 점검 대상은 `- 확인: [ ]`(미체크) 항목 전부이며, **오래된 것(위쪽)부터** 순서대로 처리한다. 대상 탐색(`---` 구분선 이후 본문만 검색해 상단 템플릿 매치를 제외):
   ```bash
   for f in docs/report/report_claude.md docs/report/report_gpt.md; do
     awk -v file="$f" '/^---$/{body=1; next} body && /확인: \[ \]/{print file":"FNR}' "$f"
   done
   ```
3. `확인:` 줄이 아예 없는 과거 항목은 미체크와 동일하게 취급한다(점검 후 항목 끝에 `- 확인: [x] ...` 한 줄을 추가한다).
4. 점검 없이 체크만 하는 것을 금지한다. 체크는 아래 절차를 전부 수행했다는 서명이다.

## A. 구현 보고(report_claude.md) 점검 — 리뷰 LLM용

미체크 항목마다 다음을 수행한다.

1. **사실 대조** — "작업"에 언급된 파일·설정·테스트가 실제로 존재하고 서술과 일치하는지 코드를 직접 열어 확인한다. 보고 문장만 믿고 넘어가지 않는다.
2. **검증 재현** — "검증"의 주장 중 재현 가능한 것(`./scripts/verify.sh` 또는 `npm run verify`)은 직접 실행해 green을 확인한다. 재현 불가한 주장(red→green 실측, 임시 오염 후 원복 등)은 해당 테스트 코드를 읽고 주장이 성립하는 구조인지 판단한다.
3. **정합성 점검** — "미결"의 BLOCKED·후속 작업이 [backlog.md](../backlog.md)·[checklist.md](../checklist.md)의 현재 상태와 일치하는지, 보고가 체크했다고 주장하는 checklist 항목이 실제 통과 근거를 갖는지 확인한다.
4. **요청 리뷰 우선** — 보고가 "GPT 리뷰 요청" 등으로 지목한 부분을 가장 깊게 본다.
5. **원칙·계약 점검** — 변경이 [CLAUDE.md](../../CLAUDE.md) 절대 원칙(추천 금지, 환각 금지, 기준시점, 출처, 결정론, 정합성, 오류 구분, 보안·격리, 주문 분리)과 [skills.md](../skills.md) 계약을 위반하지 않는지 본다.

점검 결과 기록:

6. 결과를 [report_gpt.md](report_gpt.md) 하단에 shell append로 추가한다. 형식은 그 파일 상단 템플릿을 따르고, `리뷰 대상`에 점검한 보고 항목의 타임스탬프와 Task ID를 적는다.
7. report_claude.md의 해당 항목 `- 확인: [ ]`를 체크한다. 판정이 "수정요청"이어도 점검 자체는 끝났으므로 체크한다 — 수정 반영 추적은 report_gpt.md 쪽 항목의 `확인:` 체크박스가 담당한다.

## B. 리뷰 피드백(report_gpt.md) 반영 — 구현 agent용

새 Task 착수 전([instructions.md](../instructions.md) 작업 시작 절차 1단계) 미체크 항목을 확인하고, 항목마다 다음을 수행한다.

1. "발견"·"계약 위반"·"권고"를 읽고 타당성을 판단한다. 타당하면 수정하고, 동의하지 않으면 반박 근거를 남긴다.
2. 반영 내용 또는 반박 근거를 report_claude.md의 다음 작업 보고("작업" 또는 "미결")에 기록한다.
3. report_gpt.md의 해당 항목 `- 확인: [ ]`를 체크한다.

## 판정 기준

- **승인**: 사실 대조·검증 재현·정합성 점검에 문제가 없고 원칙·계약 위반이 없음.
- **수정요청**: 보고와 실물이 다르거나, 검증 주장이 재현되지 않거나, 원칙·계약 위반이 있음. 발견 사항에는 파일:라인을 명시하고 심각도 순으로 적는다.
