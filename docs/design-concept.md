# CareerSignal 디자인 컨셉

## 1. 방향 요약

CareerSignal은 짙은 인디고 앱 셸과 낮은 채도의 의미색을 사용하는 차분한 리서치 리포트형 SaaS 인터페이스다. 채용공고의 요구사항을 단순 나열하지 않고, 사용자가 지원 준비의 우선순위를 빠르게 읽을 수 있도록 숫자·구현 범위·다음 행동을 순서대로 배치한다.

이 문서는 실제 서비스 `product/`와 정적 화면 검증용 `prototype/`의 시각 체계에 적용한다. 독립적인 프로젝트 소개 화면인 `project-intro/`는 별도 산출물이다.

앱 셸에는 짙은 인디고 고정 상단바와 밝은 하늘색 본문 배경을 사용한다. 본문 카드는 반투명 흰색·블러·흰색 테두리를 결합한 공통 글래스 재질로 통일하고, 요약 지표와 상태의 차이는 숫자·배지·그래프의 낮은 채도 의미색으로 표시한다.

## 2. 핵심 원칙

- **분석에서 행동으로**: 반복 요구사항을 직무 공통 기대치, 공통 기대치와의 차이, 합격 전략, 준비 로드맵으로 연결한다.
- **구현 범위를 보여주기**: 기술명보다 데이터 흐름·예외 처리·성능을 어느 수준까지 다뤄야 하는지 설명한다.
- **근거 있는 정보 밀도**: 공고 건수와 비율은 짧게 보여 주고, 해석은 필요한 곳에만 둔다.
- **절제된 시각 언어**: 짙은 인디고 상단바, 밝은 하늘색 배경, 공통 글래스 카드와 낮은 채도의 의미색으로 정보 위계를 만든다.

## 3. 대상 사용자와 톤

대상은 채용공고를 읽어 본 적은 있지만 무엇을 먼저 준비할지 판단하기 어려운 디지털·기술 분야 취업 준비 대학생이다. 화면 구조는 특정 기술 스택에 의존하지 않고 직무별 요구사항·증명 방식·학습 결과물을 같은 정보 위계로 표현한다.

- 공고 문장을 그대로 반복하지 않고, 준비 기준을 설명하는 문장으로 쓴다.
- 초보자를 위한 서비스이되 과도한 게임화나 튜토리얼 문구는 사용하지 않는다.
- 숫자를 보여 주는 블록에는 표본 수를 병기해, 읽는 사람이 근거의 크기를 함께 판단하게 한다.

## 4. 화면 구조

다섯 화면은 `직무 선택 → 통계 분석 → 채용공고 해석 → 합격 전략 → 준비 로드맵` 순서다.

- 모든 화면은 고정 상단바(`TopBar`)에 브랜드와 해당 단계(STEP n/5)를 둔다. 분석 화면들에는 분석 직무와 이전 화면으로 이동하는 링크를 추가한다.
- 직무 선택 화면은 가운데 정렬된 단일 카드에 안내 문구, 직무 목록, 분석 항목 미리보기, CTA를 배치한다.
- 통계 분석·채용공고 해석·합격 전략·준비 로드맵은 가운데 정렬한 본문 오른쪽에 고정형 글래스 목차(`SectionNav`)를 둔다. 넓은 화면에서는 본문을 화면 중앙에 두고 목차는 그 오른쪽에 배치한다. 목차 항목은 본문 섹션과 1:1로 대응하고, 스크롤 위치에 따라 현재 항목을 표시한다.
- 채용공고 해석·합격 전략·준비 로드맵은 본문 맨 위에 범위 전환 블록(`ScopeSwitch`)을 둔다. 세 화면에서 범위를 고르는 자리는 이 블록 하나이며, 본문 섹션 안에는 범위를 고르는 요소를 두지 않는다.
- 활성 분석 결과가 없는 직무를 열면 본문 대신 안내 카드(`AnalysisNotice`)를 한 장 두고, 직무 다시 선택을 다음 행동으로 제시한다.
- 화면 폭이 줄어들면 본문을 단일 열로 전환하고, 오른쪽 목차는 상단의 가로 스크롤 목차로 바꾼다. 폭 기준값과 표시 밀도는 [디자인 토큰](design-tokens.md)에 있다.

범위 전환 블록은 세 단이 위에서 아래로 좁혀 가는 구조다.

1. 범위 종류 — 직무 전체, 기업군, 개별 공고, 내가 입력한 공고. 마지막 항목은 사용자가 공고를 입력한 뒤에만 나타난다.
2. 기업군 — 범위 종류가 기업군이거나 개별 공고일 때 표시한다. 개별 공고에서는 아래 목록을 좁히는 거르개로 함께 쓰인다.
3. 공고 목록 — 범위 종류가 개별 공고일 때 표시하며, 회사명·공고 제목·기업군으로 검색한다.

블록 아래 한 줄이 지금 보고 있는 범위를 문장으로 다시 밝힌다. 요청한 개별 공고의 결과가 없어 더 넓은 범위의 결과를 표시할 때는 그 사실을 같은 자리에 적는다.

## 5. 화면별 정보 구성

### 5.1 직무 선택

직무 목록을 버튼 한 줄로 늘어놓아 분석의 시작점을 고르게 한다. 아래 미리보기는 통계 분석, 채용공고 해석, 합격 전략, 준비 로드맵을 설명한다.

### 5.2 통계 분석

리얼리티 → 기술 → 해석 → 데이터 순서의 10개 블록으로 구성한다([기획서 9.2장](plan.md#92-채용공고-통계-분석-화면) 참고).

1. 리얼리티: KPI 지표 카드, 직무 외 요구 범위, 필수 인플레이션, 숨은 난이도
2. 기술: 기술 빈도, 함께 요구되는 기술 조합과 구현 수준, 증가·유지·감소 추이
3. 해석: 라벨 vs 현실, 기업군 성향 히트맵
4. 데이터: 요구 항목 전체표(기본 접힘)

각 블록에는 표본 수와 신뢰도를 병기하고, 요구 항목 전체표는 채용공고 해석 화면과 같은 데이터를 사용한다.

### 5.3 채용공고 해석

직무 공통 기대치·기업군이 더 요구하는 지점·개별 공고·내 공고 직접 분석의 네 섹션을 항상 표시하고, 맨 위 범위 전환 블록의 선택이 앞의 세 섹션 내용을 바꾼다. 직무 공통 기대치 카드는 통계 근거(등장률·필수율)를 병기하고, 추가 요구 카드는 공통 기대치와 차이가 없는 항목까지 명시한다. 개별 공고는 원문의 모든 문장에 세 종류 주석 — 직무 공통 기대치(회색 번호+라벨), 숨은 의미(파란 하이라이트), 회사 특징(노란 하이라이트) — 을 달고, 종합 해석과 주석 종류별 해석 탭으로 보여 준다.

내 공고 직접 분석 섹션(`PostingAnalyzePanel`)은 공고 원문 입력창, 글자 수 표시, 분석 실행 버튼, 원문 사용 범위 안내를 한 카드에 담는다. 분석 결과는 개별 공고와 같은 원문·해석 나란히 보기로 표시하고, 합격 전략과 준비 로드맵은 요약 카드 두 장으로 보여 준 뒤 상세는 해당 화면으로 넘긴다. 입력한 공고는 세 화면의 범위 전환 블록에 `내가 입력한 공고` 범위로 남는다. 즉시 분석을 실행할 수 없을 때는 직무 일반 결과를 대신 보여 주고 그 사실을 카드 위에 밝힌다.

### 5.4 합격 전략

준비 현황 카드, 체크리스트 표 [요구 항목 · 근거 · 필요 산출물/활동 · 활용처 · 보유 여부], 활용처별 내용(자소서 소재, 포트폴리오 강조점, 예상 면접 질문)을 함께 배치한다. 범위 전환 블록의 선택은 체크리스트와 전략 전체를 바꾸고, 보유 체크는 준비 현황 숫자와 체크 표시만 바꾼다. 포트폴리오·자소서·면접 전략은 체크 여부와 관계없이 유지한다.

### 5.5 준비 로드맵

프로젝트 로드맵은 순서형 타임라인, 학습 전략은 병행형 트랙으로 배치한다. 각 항목은 단계, 기간, 우선순위, 채워지는 체크리스트 항목, 산출물, 학습 깊이와 추천 이유를 제공한다. 범위 전환 블록의 선택이 기본 내용을 바꾸고, 체크 적용은 저장된 프로젝트·학습 후보의 완료 표시와 우선순위를 재조합한다.

## 6. 표현 규칙

- 상단바는 짙은 인디고 배경과 흰색 워드마크를 사용한다.
- 오른쪽 목차는 반투명 흰색·블러 글래스를 사용한다.
- 카드에는 반투명 흰색 배경, 흰색 테두리, 블러와 푸른 그림자를 사용한다. 표와 긴 원문을 담는 면은 일반 카드보다 불투명하게 유지한다.
- 직무 선택 미리보기에는 서로 가까운 저채도 인디고·블루 면색을 사용한다. 통계 분석·합격 전략·준비 로드맵의 상단 KPI 카드는 같은 블루 글래스 면으로 통일하고, 의미색은 숫자·배지·그래프에만 사용한다.
- 버튼, 칩, 지표는 고정된 크기와 간격을 유지해 내용 변화로 레이아웃이 흔들리지 않게 한다.
- 제목은 결론을 먼저 말하고, 보조 문장은 해당 결론을 읽는 기준을 제공한다.
