# 잔소리봇 디자인 컨셉

기존에는 '할 일 관리 서비스'에 가까운 느낌이었다면, 지금은 **'잔소리도 해주지만 끝까지 함께 걸어주는 AI 동행자'**라는 방향으로 디자인 컨셉을 발전시켰습니다.

서비스 이름은 **잔소리봇**을 그대로 유지합니다.

여기서 '잔소리'는 사용자를 혼내거나 압박하는 것이 아니라, 사용자가 공부를 미루는 순간마다 상황에 맞게 먼저 다가와 말을 걸고, 결국 다시 시작할 수 있도록 도와주는 AI의 따뜻한 개입을 의미합니다.

## 서비스 컨셉

잔소리봇은 자주 미루고 공부 시작을 어려워하는 대학생을 위한 AI 학업 실행 도우미입니다.

핵심은 사용자를 관리하거나 감시하는 것이 아니라, **공부를 시작하기 어려운 감정을 이해하고, AI가 적절한 순간마다 개입하여 작은 첫 행동(Micro-task)을 제안하고 다시 시작하도록 돕는 것**입니다.

사용자는 혼자 공부하는 것이 아니라 AI와 함께 공부 여정을 이어가는 경험을 하게 됩니다.

## 디자인 방향

현재 UI는 밝은 중성 배경, 흰색 패널, 얇은 테두리와 제한적인 그림자를 기반으로
합니다. 반투명 패널과 blur는 Journey 배경 위 정보 가독성을 보호하는 일부 영역에만
사용하며, 과도한 glassmorphism이나 강한 gradient는 사용하지 않습니다.

사용자가 서비스를 사용하는 동안 항상 다음과 같은 느낌을 받을 수 있도록 하고 싶습니다.

- 차분함
- 따뜻함
- 프리미엄
- 여유로움
- 부담 없이 시작할 수 있는 분위기

정보를 많이 보여주는 생산성 도구가 아니라, 사용자가 **"이 정도라면 지금 시작할 수 있겠다."** 라는 감정을 느끼도록 만드는 것이 가장 중요합니다.

### 핵심 색상

| 역할 | 색상 | 사용 범위 |
| --- | --- | --- |
| 배경 | `#f4f5f7` | 앱의 밝은 중성 배경 |
| 패널 | `#ffffff` | 카드와 정보 패널 |
| 주 텍스트 | `#1e2430` | 제목과 핵심 정보 |
| 보조 텍스트 | `#656d7a` | 설명과 메타 정보 |
| 브랜드 포인트 | `#4c5fd5` | Primary CTA와 포커스 표시 |
| Lv1 | `#78cfc3` | 민트, 가벼운 개입 |
| Lv2 | `#9285bc` | 보라, 행동을 더 작게 제안 |
| Lv3 | `#d77f91` | 코랄·더스티 로즈, 진지한 개입 |
| Lv4 | `#c94a43` | 부드러운 적색, 가장 명확한 개입 |

레벨색은 Badge와 진행바처럼 현재 개입 수준을 설명하는 요소에 제한적으로 사용합니다.
진행 중 상태는 중립색, 마감 상태는 별도의 deadline 표현을 유지해 모든 Badge가 동시에
강하게 보이지 않도록 합니다.

## 핵심 경험

이 서비스에서 가장 중요한 경험은 **'공부를 하나의 여정으로 표현하는 것'**입니다.

공부를 시작하면 잔소리봇이 사용자와 함께 걷는 모습으로 Focus 시간을 표현합니다.

사용자는 단순히 타이머를 보는 것이 아니라, AI 동행자와 함께 한 걸음씩 나아가는
경험을 하게 됩니다.

공부를 완료하면 성공 캐릭터와 짧은 시각 효과로 여정을 마무리합니다.

공부는 체크리스트가 아니라 하나의 여정처럼 느껴져야 합니다.

실제 이동 경로, 목적지 도착 애니메이션과 Walking 프레임 애니메이션은 현재 구현
범위가 아닙니다.

## 잔소리 시스템

잔소리봇의 가장 중요한 특징은 **레벨별 개입(Intervention System)**입니다.

사용자가 할 일을 시작하지 않고 반응하지 않으면 잔소리봇이 먼저 다가와 상황에 맞게 개입합니다.

레벨이 올라갈수록 말투와 개입 강도는 조금씩 강해지지만, 절대 사용자를 비난하거나 죄책감을 주어서는 안 됩니다.

사용자가 느껴야 하는 감정은

> "혼나는 기분"

이 아니라

> "잔소리봇이 끝까지 나를 포기하지 않고 응원해 주는구나."

입니다.

잔소리는 서비스의 핵심 아이덴티티이며, 동시에 AI가 사용자를 가장 따뜻하게 도와주는 방식입니다.

## 날씨 시스템

잔소리 강도는 빨간 경고나 위험 색상이 아니라 자연스러운 날씨 변화로 표현합니다.

- ☀️ 맑음
- ⛅ 약간 흐림
- ☁️ 흐림
- 🌧️ 비
- ⛈️ 폭풍

날씨는 잔소리 레벨을 시각적으로 표현하는 장치입니다.

날씨가 변하더라도 전체 분위기는 항상 아름답고 차분하며 읽기 쉬워야 합니다.

폭풍 역시 위협적인 느낌이 아니라, "잔소리봇이 걱정하며 기다리고 있다"는 감정을 전달해야 합니다.

현재는 레벨별로 제작된 Shared Journey 배경을 그대로 사용하며, 별도의 날씨
오버레이를 실시간으로 합성하지 않습니다.

## Shared Journey 적용 범위

Shared Journey는 다음 화면에 실제로 적용되어 있습니다.

- **Landing**: 서비스의 여정 개념과 Lv0~Lv4 날씨 변화를 소개합니다.
- **Home**: 대표 active Task를 레벨별 캐릭터와 날씨가 있는 Journey Hero로 보여 줍니다.
- **Focus**: 진입 당시 레벨의 배경과 Walking 캐릭터를 세션 동안 유지합니다.
- **Completion**: 성공 캐릭터와 sparkles로 완료 경험을 연결합니다.

새벽·오전·오후·밤에 따라 배경이 달라지는 시간대 테마는 초기 아이디어이며 현재
구현되지 않았습니다.

## 잔소리봇 캐릭터

잔소리봇은 관리자도 아니고 선생님도 아닙니다.

사용자의 앞에서 끌고 가는 존재도 아닙니다.

항상 사용자 옆에서 함께 걸어가는 AI 동행자입니다.

평소에는 조용히 함께 걸어가고, 사용자가 멈추면 먼저 다가와 말을 걸고, 다시 시작하면 함께 기뻐하는 존재입니다.

귀엽지만 너무 어린 느낌은 아니며, 미래적인 분위기와 친근함을 동시에 가진 캐릭터를 지향합니다.

현재 캐릭터는 통통한 흰색 3D 몸체, 검은 유광 얼굴 화면, 양옆의 링 형태 스피커,
발광 안테나, 스카프와 짧은 팔다리로 정체성을 유지합니다. Lv0~Lv4에서는 같은
캐릭터의 표정과 포즈, 안테나·스카프의 색상 강도가 점차 단호해집니다.

- Navbar와 TaskCard는 작은 얼굴 이미지를 사용합니다.
- Landing, Home Hero와 Nudge Modal은 전신 캐릭터를 사용합니다.
- Focus는 레벨별 Walking 포즈를 사용합니다.
- Completion은 `nagbot_success.png`와 제한적인 sparkles를 사용합니다.

캐릭터는 모든 영역을 채우는 장식이 아니라, 필요한 화면에서 정보와 핵심 행동을
보조하는 동행자로 사용합니다. 저장소에 남아 있지만 실제 화면에서 import하지 않는
초기 에셋은 현재 디자인 기준으로 간주하지 않습니다.

## 화면별 디자인 역할

- **Landing**: 가치 제안과 사용 흐름을 가장 강하게 보여 주되 캐릭터 반복을 줄입니다.
- **Register**: 설명을 최소화한 단일 Form을 중심에 두고 캐릭터는 데스크톱 보조 영역에만 둡니다.
- **Home**: Summary보다 Journey Hero가 강하게 보이며, active·waiting·done의 정보량을 구분합니다.
- **Nudge Modal**: 레벨별 캐릭터와 색을 사용하되 메시지와 첫 행동 CTA를 먼저 읽게 합니다.
- **Focus**: Journey 배경과 Walking 캐릭터로 몰입감을 주면서 Task, 타이머와 종료 행동을 보호합니다.
- **Completion**: 과한 게임 보상 대신 성공 캐릭터와 짧은 효과로 완료를 축하합니다.
- **History**: compact Summary와 그래프가 리스트·캘린더 기록 탐색을 보조합니다.

각 화면의 구성과 이동 조건은 `docs/wireframe.md`를 기준으로 합니다.

## 반응형과 접근성

앱 본문과 Navbar는 주로 `900px` 중앙 정렬을 사용하며, Landing은 더 넓은 전용
레이아웃을 사용합니다. 데스크톱에서는 필요한 영역을 두 열로 구성하고, 태블릿과
모바일에서는 핵심 정보 순서를 유지한 채 한 열 또는 compact grid로 전환합니다.

현재 구현은 주요 링크·버튼·입력의 `focus-visible`, 입력 label과 오류 연결, Modal의
dialog 이름, 장식 이미지의 빈 `alt`, 그래프의 접근 가능한 이름을 포함합니다.
Landing, Lv4 Nudge와 Completion의 비필수 애니메이션은
`prefers-reduced-motion`에서 줄이거나 제거합니다. 모든 브라우저와 보조기기에서의
완전한 접근성 검증까지 완료된 것으로 표현하지는 않습니다.

## 앞으로 디자인에서 중요하게 생각하는 점

앞으로 모든 화면은 단순히 예쁜 UI를 만드는 것이 아니라, **"잔소리도 해주지만 끝까지 함께 걸어가는 AI 동행자와 공부하는 경험"**이 자연스럽게 느껴져야 합니다.

모든 인터랙션, 애니메이션, 화면 구성은 이 철학을 중심으로 설계해 주세요.

사용자가 서비스를 사용할 때 **"공부를 관리받는 느낌"이 아니라**, **"잔소리도 해주지만 결국 내 편인 AI와 함께 오늘의 여정을 이어가는 느낌"**을 받을 수 있도록 디자인해 주세요.
