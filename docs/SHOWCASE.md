# Later — 저장에서 재발견까지 이어지는 AI 콘텐츠 인박스

> 저장은 끝이 아니라, 다시 쓰기 위한 시작이어야 합니다.

## 한 줄 소개

Later는 인터넷에서 발견한 URL·텍스트·이미지 꿀팁을 한곳에 저장하면 AI가 맥락을 읽어 한국어 제목, 핵심 요약, 카테고리로 정리하고 필요할 때 다시 꺼내 보게 만드는 콘텐츠 인박스입니다.

## 해결하려는 문제

인터넷과 SNS에는 생활, 공부, 취업, 쇼핑, 뷰티 등 유용한 정보와 꿀팁이 끊임없이 쏟아집니다. 사용자는 나중에 보려고 북마크, 메신저, 메모 앱, 스크린샷에 저장하지만 정보가 쌓일수록 무엇을 왜 저장했는지 잊고 다시 열어보지 않게 됩니다. 긴 콘텐츠를 매번 처음부터 읽어야 하는 부담도 재확인을 어렵게 만듭니다.

Later는 이 문제를 **저장 비용은 낮추고, 재발견 가능성은 높이는 경험**으로 해결합니다.

## 핵심 경험

1. **무엇이든 한곳에 저장**<br>
   URL, 일반 텍스트, JPEG·PNG·WebP 이미지를 같은 입력 흐름에서 보관합니다.

2. **AI가 맥락까지 이해**<br>
   Gemini가 URL 메타데이터와 이미지 내용을 함께 분석해 읽기 좋은 한국어 제목과 핵심 요약을 만듭니다.

3. **정리하지 않아도 자동 분류**<br>
   대분류와 소분류를 자동 생성하고, 검색과 카테고리 필터로 원하는 자료에 빠르게 도달하게 합니다.

4. **다시 보고, 다 봤다면 가볍게 정리**<br>
   카드에서 요약과 원문을 확인하고, 소비한 콘텐츠는 스와이프로 아카이브합니다.

## 대상 사용자

- SNS·커뮤니티·유튜브에서 유용한 꿀팁을 자주 저장하는 사용자
- 북마크와 스크린샷이 쌓여 필요한 정보를 다시 찾지 못하는 사용자
- 긴 콘텐츠의 핵심을 요약으로 빠르게 확인하고 싶은 사용자

## 차별점

- 단순 북마크가 아니라 **저장 순간부터 재발견을 준비**합니다.
- URL 메타데이터뿐 아니라 이미지 내용까지 함께 읽는 **멀티모달 분석**을 적용했습니다.
- AI 응답을 그대로 신뢰하지 않고 Structured Output과 런타임 검증을 거칩니다.
- Gemini가 느리거나 실패해도 규칙 기반 분류로 저장을 이어가는 **graceful fallback**을 설계했습니다.
- 메타데이터 수집 과정에 사설 IP 차단, 리다이렉트 재검증, timeout, 응답 크기·형식 제한을 적용했습니다.

## 다음 단계

저장 후 잊힌 콘텐츠를 적절한 시점에 다시 꺼내 보도록 돕는 리마인더 알림을 온보딩 시안과 제품 로드맵으로 설계했습니다. 현재 버전에는 실제 푸시 발송 기능이 포함되지 않았으며, 알림 권한과 발송 주기, 사용자별 재확인 신호를 검증한 뒤 구현할 예정입니다.

## 구현 구조

- **Next.js · React · TypeScript**: 설치 가능한 PWA와 저장·검색·분류·아카이브 경험
- **Express**: URL 메타데이터 수집, 입력 검증, Gemini 연동 API
- **Gemini API**: 텍스트·웹 메타데이터·이미지의 구조화된 제목·요약·분류
- **Supabase Database & Storage**: 콘텐츠 데이터와 이미지 파일의 분리 저장
- **Vitest**: 분류, 메타데이터, API, UI 핵심 경로의 회귀 검증

## AI와 함께 개발한 방식

사람이 문제와 사용자 경험, 완료 기준을 결정하고 Codex가 코드베이스 분석, 구현, 테스트, 문서화를 수행했습니다. 기능마다 브라우저에서 실제 URL과 이미지를 저장해 결과를 확인하고, 실패 사례를 테스트와 검증 로직으로 되돌렸습니다. AI가 코드를 생성하는 데서 끝내지 않고 **요구사항 → 구현 → 실제 검증 → 회귀 방지**의 반복 가능한 개발 워크플로를 만든 것이 이번 프로젝트의 핵심 학습입니다.
