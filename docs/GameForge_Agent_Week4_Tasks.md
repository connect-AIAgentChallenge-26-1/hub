# GameForge Agent — 4주차 작업 세분화 (Day 15~18)

> Day 1~14는 이전 설계(9단계 전부 채팅 기반, 8단계는 최초 저장소 분석 리포트 참고, 유저 격리 없음, PAT 대신 OAuth·Gemini는 이미 반영된 상태)로 완료됐다. 이후 논의된 아키텍처 변경(v5~v9)은 `GameForge_Agent_Week3_Tasks_Day11-14.md`를 소급 수정하지 않고, 여기 Day 15~18로 새로 정리한다. **전부 "이미 동작하는 걸 다르게 동작하게 바꾸는" 마이그레이션 작업**이라, 각 Day 시작 전에 항상 "지금 코드가 실제로 어떻게 되어있는지" 먼저 파악하고 진행한다.

> **참고**: Day 14 완료 이후 실사용 테스트 중 발견된 자잘한 버그(steps.json이 done으로 굳어있던 것, 1단계 문서 저장 안 되던 것)와 부가 기능(리셋 스크립트, 429 quota 에러 처리, 데모 모드, "지금까지 내용으로 문서 만들기" 버튼)은 각각 별도 프롬프트로 이미 처리했다는 전제로 아래 계획을 짰다. 아직 안 했다면 Day 15 착수 전에 먼저 처리할 것.

## Day 15 — v5: 7·9단계를 채팅 없는 자동 생성으로 전환

### 사전 확인
- 지금 7단계(코드 생성), 9단계(문서화)가 실제로 채팅 기반으로 동작하는지 확인 (WorkspaceMainPanel이 이 두 Step에서도 ChatThread를 렌더링하고 있는지)

### 7단계 — Code Generation Agent
- Step 진입 시 채팅 없이 즉시 Agent 호출로 변경
- Roslyn 분석 결과에서 네임스페이스 컨벤션을 감지해 프롬프트에 반영 (분석기가 namespace 필드를 안 뽑고 있다면 추가)
- 생성 완료 후 곧바로 4.6 커밋 리뷰 화면(FileChangeList)으로 연결 — 문서 미리보기 없음
- 로딩 상태 "코드를 생성하는 중…" 표시

### 9단계 — Documentation Agent
- Step 진입 시 채팅 없이 즉시 Agent 호출
- 입력: 1~8단계 전체 산출물(문서 6개 + 7~8단계 커밋된 코드 변경 요약)
- 톤: PR 설명처럼 — 무엇을 왜 만들었는지 요약
- 결과는 MarkdownEditorPane으로 바로 진입 (채팅으로 돌아가는 경로 없음)

### 프론트엔드 공통
- WorkspaceMainPanel에서 Step이 7 또는 9일 때 ChatThread/ChatInput을 렌더링하지 않고, "자동 생성 중" 로딩 → 결과 화면으로 바로 전환되는 분기 추가
- 1~6단계는 기존 채팅 흐름 그대로 유지 (건드리지 않음)

### 공통 — Approve 시 즉시 실커밋
- 9단계 Approve가 별도 확인 없이 바로 실제 docs/ 커밋으로 이어지는지 확인
- 7단계는 기존 커밋 리뷰 화면(파일 체크박스 선택)을 그대로 유지 — 채팅만 건너뛰는 것이지 리뷰 화면까지 건너뛰는 게 아님

**Day 15 완료 기준**: 7단계 진입 시 채팅 없이 곧바로 코드 생성이 시작되고 생성된 코드의 네임스페이스가 기존 컨벤션을 따른다. 9단계 진입 시 채팅 없이 곧바로 PR 설명 형태 문서 초안이 나오고, 수정 후 Approve하면 바로 실제 GitHub에 커밋된다.

## Day 16 — v6: 커밋 직전 Syntax 검증 + v8: 8단계 입력 전환

> 두 변경이 서로 맞물려 있어(둘 다 8단계 흐름을 건드림) 하루에 묶었다.

### v6 — 커밋 직전 최소 문법 검증
- `tools/analyzer/`에 파싱 전용 검증 모드 추가: 코드 문자열을 받아 `CSharpSyntaxTree.ParseText()`로 파싱 후 `GetDiagnostics()`의 Error 심각도만 확인 (컴파일/타입 체크 아님)
- file-changes 저장 시 각 파일의 `newContent`에 대해 이 검증을 돌려 `syntaxValid`, `syntaxErrors` 필드 추가
- `GET /api/steps/{id}/file-changes` 응답에 포함
- FileChangeList에서 문법 오류 있는 파일은 경고 뱃지 + 기본 체크 해제로 표시 (강제 커밋은 허용, 기본값만 안전하게)

### v8 — 8단계(Code Review Agent, 구 Refactoring Agent) 입력 전환
- 입력을 "최초 저장소 분석 리포트"에서 **"7단계가 만든 코드(`newContent`)"**로 교체
- 8단계 진입 시 7단계 파일들만 대상으로 Roslyn 분석기(위 v6 파싱 모드를 확장)를 다시 돌려 메서드 수 등 구조 지표를 뽑아 Agent 프롬프트에 전달 (God Class 판단 근거 — 최초 저장소 전체 재분석 아님, 7단계 파일만 대상으로 하는 가벼운 호출)
- 8단계 호출 전 GitHub에서 파일을 다시 읽어올 필요 없음 — 7단계의 `newContent`를 그대로 "현재 내용"으로 사용
- 8단계도 동일한 구조화 JSON 포맷(`newContent`)으로 출력하고, v6 문법 검증도 동일하게 적용

**Day 16 완료 기준**: 문법적으로 유효하지 않은 코드가 생성되면 커밋 리뷰 화면에서 경고와 함께 기본 체크 해제 상태로 표시된다. 8단계 진입 시 최초 분석 리포트가 아니라 7단계 산출물을 입력으로 받아 그것에 대한 리뷰/개선 제안이 나온다.

## Day 17 — v9: 7단계에 기존 코드 컨텍스트 포함

### 관련 기존 파일 탐색
- 4단계(클래스 설계) 문서 텍스트에서 클래스명·상속 관계 파싱 (정규식/간단 텍스트 매칭 수준으로 충분)
- 최초 저장소 분석(Roslyn) 결과의 클래스 목록과 이름 대조 → 일치하는 기존 클래스의 파일 경로 확보
- 매칭된 파일들만 GitHub API로 현재 전체 내용 읽어오기 (설계 문서가 언급 안 한 파일은 읽지 않음 — 컨텍스트/비용 통제)

### Code Generation Agent 프롬프트 수정
- 입력에 위에서 찾은 기존 파일 내용 추가
- "기존 코드가 있으면 그 위에서 이어서 확장하라", "빈 상태에서 새로 쓰지 마라" 지시 추가
- `changeType`을 Agent가 스스로 판단하게 변경 (매칭된 기존 클래스 수정 → `modified`, 완전 신규 → `new`) — 지금까지 `new`로 고정되어 있었다면 이 부분도 같이 고침

**Day 17 완료 기준**: 설계 문서가 기존 클래스(예: PlayerController)를 언급하면 실제로 그 파일의 현재 내용이 Agent 입력에 포함되고, 결과 `changeType`이 `modified`로 정확히 판단된다. 언급 안 된 파일은 읽지 않는다.

## Day 18 — v7: 유저별 데이터 격리 + 전체 통합 점검

> 규모가 있는 작업이라 하루 안에 못 끝나면 다음 날로 이어가도 됨. 대신 이 작업 하나만 온전히 진행 — 다른 기능 추가는 하지 않는다.

### 0단계: 현재 라우트 전수 조사
- 지금 존재하는 모든 `/api/*` 라우트와, 각각이 `data/` 아래 어떤 경로를 읽고/쓰는지 목록화

### 세션 구조 변경
- `data/session.json`(단일) → `data/sessions/{session_id}.json`(다중)으로 전환
- `github_user_id`(숫자, username 아님) 기준으로 식별
- OAuth 콜백에서 세션 생성 + 서명된 쿠키 발급

### 세션 해석 미들웨어
- 로그인/콜백 라우트를 제외한 모든 `/api/*`에 공통 적용
- 쿠키의 `session_id` → `sessions/{id}.json` 조회 → `req.userId` 설정, 없으면 401

### 데이터 경로 전면 이전
- `data/project.json`, `steps.json`, `documents/`, `messages/`, `checklist/`, `file-changes/` 전부 `data/users/{userId}/` 아래로 이동
- 공통 헬퍼 함수(`getUserDataPath(userId, ...)`)로 경로 조립 통일 — 라우트마다 따로 조립하지 않기
- 파일 락(mutex)을 유저 디렉토리별로 분리

### 통합 점검 (v5~v9 전체를 아우르는 최종 확인)
- 로그인 → 저장소/Branch 선택 → 분석 → 1~9단계(자동 생성 2개 포함) → 실제 커밋까지 처음부터 끝까지 시연
- 서로 다른 GitHub 계정 두 개로 교차 로그인해서 데이터가 안 섞이는지 확인
- 이번 기회에 `docs/GameForge_Agent.md`, `GameForge_Agent_Dev_Plan.md`의 "제외한 것" 목록도 실제 구현 현황에 맞게 갱신

**Day 18 완료 기준**: 계정 두 개로 각각 로그인해 각자 작업해도 데이터가 섞이지 않는다. v5~v9가 반영된 상태로 1~9단계 전체가 로그인부터 실제 커밋까지 새로고침 없이 시연 가능하다.
