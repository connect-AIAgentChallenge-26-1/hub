# Resource Extraction Skill

## Purpose

기획 자료에 명시된 리소스와 그로부터 필요한 제작 태스크 후보를 일관되게 추출한다.

## Rules

- 원문에 등장하거나 명확히 요구되는 리소스만 추출한다.
- 같은 이름이라도 역할이나 사용 위치가 다르면 별도 후보로 두고 차이를 적는다.
- 이름이 없으면 임의로 짓지 않고 설명과 `TBD`를 사용한다.
- 후보마다 파일 경로와 가능한 근거 위치를 기록한다.
- 기존 inventory와 같은 이름, 타입, 역할을 비교해 중복 가능성을 표시한다.
- 구현 방식, 수량, 품질 기준이 원문에 없으면 추론하지 않는다.

## Task Mapping

- 규칙·수치·문서 보완: `planning`
- 게임 로직·데이터 처리: `programming`
- 캐릭터·배경·UI 시각 리소스: `art`
- 음악·효과음·보이스: `sound`
- 검증 항목과 재현 확인: `qa`

태스크 후보는 필요한 이유와 원본 리소스를 연결한다. 담당자, 마감일, 완료 상태는 추정하지 않는다.
