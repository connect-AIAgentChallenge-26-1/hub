밥약 매칭 서비스

"언제 볼까 + 어디서 볼까"를 한 번에

친구들 캘린더를 모아 모두가 비는 시간을 자동으로 찾고, 그 시간에 맞춰 위치·음식 카테고리 기반 맛집까지 추천하는 대학생 밥약 서비스.

🎓 국내 대학생 대상 개인 프로젝트 4주 완성 웹 서비스
문제 정의 사용자 시나리오 핵심 기능 DB 설계 API 비기능 요구사항 MVP 범위 로드맵 리스크
1

문제 정의

대학생은 수업 시간표(에타), 개인 일정, 동아리 일정이 각각 다른 곳에 흩어져 관리된다. 친구 여러 명(보통 3~4명)과 밥약을 잡으려면 각자에게 "언제 시간 돼?"를 반복해서 물어보며 스케줄을 맞춰야 하고, 시간이 겹치는 걸 확인해도 막상 어디서 먹을지 다시 논의하느라 시간이 낭비된다.

자동화 1

모두가 비어있는 시간 찾기

여러 사람의 캘린더를 모아 비교해서 공통 공강 시간을 자동으로 계산한다.

자동화 2

맛집 추천

찾은 시간에 맞춰 위치·음식 카테고리 기반으로 맛집을 추천한다.

"언제 볼까"와 "어디서 볼까"를 한 번에 해결한다. 이것이 이 서비스의 핵심 가치다.
2

사용자 정의

주 사용자

국내 대학생

특히 시간표가 자주 바뀌는 학기 초·중반에 필요성이 크다.

사용 상황

밥약을 잡을 때

친구·동아리·스터디원과 식사 약속을 잡는 모든 순간.

기술 숙련도

일반 사용자 수준

스마트폰·웹 서비스에 익숙한 정도면 충분. 기술적 능숙함 불필요.

3

사용자 시나리오

온보딩
  1. 회원가입/로그인 — 구글 로그인 시 캘린더 읽기 권한도 동시에 요청
  2. 마이페이지에서 캘린더 추가 연동 — 에타는 공유 링크, 애플은 앱 암호 또는 webcal 링크
  3. 통합 캘린더에서 모든 일정을 한 곳에서 확인
밥약 모임 생성
  1. "새 밥약 모임 만들기" 버튼 클릭
  2. 가입된 친구를 검색해 초대
  3. 친구 수락 시 전원의 캘린더를 비교해 모두가 비는 시간대 후보를 리스트로 제시
  4. 후보 중 하나(또는 여러 개)를 선택
맛집 추천
  1. 위치 입력 — GPS 자동 또는 학교 이름 직접 입력
  2. 음식 카테고리 선택 — 한식/일식/중식/양식/카페 등
  3. 네이버+카카오 결과를 합쳐 리뷰순·평점순 상위 3~4곳을 카드로 제시
  4. 하나를 선택하면 모임 최종 확정
모임 확정 후 — 참여자 전원에게 확정된 시간·장소가 표시된다. (확장: 알림 발송)
4

핵심 기능 명세

회원 관리

두 가지 로그인

이메일/비밀번호 회원가입·로그인, 그리고 구글 OAuth 로그인(로그인 + 캘린더 읽기 권한 동시 획득).

맛집 추천

두 API 병합 + 통합 점수

네이버 지역검색 + 카카오 로컬 결과를 병합, 리뷰 수·평점을 정규화한 통합 점수로 정렬해 상위 3~4곳만 노출.

캘린더 소스연동 방식비고
구글 캘린더 OAuth 2.0, calendar.readonly 스코프 최우선 구현
에타 시간표 공유 링크 identifier로 데이터 파싱 비공식 방식, 정책 변경 리스크
애플 캘린더 webcal 공개 링크 → .ics 파싱 (1순위) 또는 CalDAV + 앱 암호 (2순위) 읽기 전용으로 충분

연동된 일정은 주기적으로(또는 수동 새로고침 시) 동기화해 EVENT 테이블에 저장하며, 마이페이지에서 연동 상태 확인과 해제가 가능하다.

공통 공강 계산 로직
참여자별 일정을 시간순 정렬 → 전원의 "바쁜 시간" 합집합 → 활동 시간(09:00~22:00)의 나머지 = 공통 공강

최소 지속 시간(예: 1시간) 이상인 구간만 후보로 제시한다.

비기능 요구사항

보안

자격증명 암호화 저장

OAuth 토큰·앱 암호는 반드시 암호화해서 저장한다. 평문 저장 금지.

에러 처리

사람이 이해하는 메시지

외부 API 실패 시 원인이 이해되는 메시지로 안내하고, 원본 에러를 그대로 노출하지 않는다.

확장성

provider 기반 구조

캘린더 소스 추가를 감안해 provider 필드 기반으로 새 소스를 붙이기 쉽게 설계한다.

배포

로컬 데모로 충분

배포는 필수가 아니다. 시간이 되면 진행한다.

네이버/카카오 맛집 추천 연동 + UI 다듬기

알려진 리스크

  • 에타 연동은 비공식 방식 정책 변경 시 깨질 수 있다. → 파싱 로직을 별도 모듈로 분리해 대응이 쉽게 설계
  • 애플 로그인에는 캘린더 권한 스코프가 없음 구글처럼 로그인과 캘린더 연동을 한 번에 처리할 수 없다. → 로그인과 캘린더 연동을 별개 절차로 안내
  • 초대 수락은 실시간이 아님 모든 참여자가 응답하기 전까지 기다려야 한다. → 전원 응답 전에는 "매칭 대기 중" 상태를 명확히 표시
