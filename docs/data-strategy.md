# CareerSignal 데이터 전략

## 1. 문서 목적

이 문서는 CareerSignal이 사용하는 자료의 계층, 출처, 획득 방식, 허용 용도, 평가 세트를 정의한다. 이 문서는 자료 정책의 기준 문서다.

저장 구조와 계보는 [지식·저장 구조](knowledge-schema.md), 실행 구조는 [아키텍처](architecture.md), 에이전트의 검색과 검증은 [에이전트 설계](agent-design.md), 분류체계와 지표는 [통계 모델](statistics-model.md)에서 다룬다.

## 2. 데이터 원칙

- 채용공고 원문과 출처 메타데이터를 분석의 원천으로 보존한다.
- 생성한 요약, Wiki, 관계는 원문을 대체하지 않는다.
- 통계는 실제 채용공고에서 직접 관찰한 요구만 집계한다.
- 회사 공식 자료는 공고 해석의 회사 맥락을 보강한다.
- 공공·표준 자료는 직무 기준과 용어 연결에 사용한다.
- 외부 전문가 자료는 준비 전략에 사용하며 기업의 직접 요구사항으로 집계하지 않는다.
- 모든 주장과 분석 결과는 원문 청크, 통계 항목, 그래프 엣지 중 하나 이상의 근거를 가진다.
- 자료는 직무, 기업, 기업군, 공고, 게시일, 수집일, 데이터 버전으로 추적한다.

## 3. 자료 계층과 허용 용도

자료 계층은 품질의 단일 순서가 아니라 허용 용도의 구분이다.

| 계층 | 자료 | 통계 집계 | 해석 | 준비 전략 |
| --- | --- | --- | --- | --- |
| A | 기업 공식 채용공고 | 사용 | 사용 | 사용 |
| B | 회사 공식 채용·기술·문화 자료 | 미사용 | 회사 맥락으로 사용 | 사용 |
| C | 공공·직무 표준 | 용어 연결에만 사용 | 직무 공통 기준 검증 | 사용 |
| D | 직무 요구와 이어지는 제3자 자료 | 미사용 | 보강 근거로 사용 | 사용 |
| E | 원문을 확인할 수 없거나 직무 요구와 이어지지 않는 자료 | 미사용 | 미사용 | 후보 탐색에만 사용 |

외부 전문가 자료가 준비 전략에 유용하더라도 기업의 요구 빈도나 특정 회사의 인재상 근거로 승격하지 않는다.

생성 데이터는 이 다섯 계층 가운데 어디에도 속하지 않는다. 계층은 수집한 원문의 출처와 허용 용도를 가르는 축이고, 생성 데이터에는 대응하는 원문 출처가 없다. 생성 데이터는 `dataset_version`으로 실 데이터와 가른다. 근거는 [ADR 0015](adr/0015-generated-dataset-version.md)에 있다.

D 계층의 편입은 내용 판정으로 결정한다. 판정의 기준은 내용이 직무 요구와 이어지는지와 주장이 검증 가능한 형태인지다. 판정 결과는 `source_assessments.reliability_score`에 0과 1 사이 값으로 기록한다. 작성자와 게시일은 확인되면 기록하고 확인되지 않아도 편입을 막지 않는다. 근거는 [ADR 0009](adr/0009-third-party-reliability.md)에 있다.

D 계층은 추론 요구의 보강 근거로 사용한다. 추론의 출발점은 공고 표현이며 D 계층 근거만으로 추론 요구를 세우지 않는다. 근거는 [ADR 0010](adr/0010-third-party-interpretation-scope.md)에 있다.

### 3.1 허용 용도 강제

`source_assessments.allowed_uses`가 자료별 허용 용도를 담는다. 검증의 자료 정책 검사가 허용되지 않은 용도의 근거를 차단한다.

```text
statistics
interpretation_context
strategy
roadmap
wiki_definition
wiki_why_required
wiki_depth_criteria
wiki_prerequisites
wiki_common_misconceptions
wiki_interview_verification
wiki_learning_sequence
```

Wiki 용도는 [지식·저장 구조](knowledge-schema.md) 8.5의 필드와 일대일로 대응한다. 필드마다 토큰이 있어야 자료 정책 검사가 필드 단위로 판정할 수 있다.

D 계층 청크가 통계 근거나 기업 요구 주장의 근거로 사용되면 검사에서 차단하고 해당 주장을 폐기한다. 자료 정책은 사람 점검이 아니라 자동 검사로 강제한다.

## 4. 요구의 세 가지 구분

공고에서 도출한 요구와 회사 자료에서 관찰한 맥락을 구분한다.

| 구분 | 정의 | 통계 반영 | 직무 공통 기대치 반영 | 필수 체크리스트 |
| --- | --- | --- | --- | --- |
| `explicit_requirement` | 공고에 명시된 요구 | 반영 | 반영 | 반영 |
| `inferred_requirement` | 공고 표현을 A·B·C 근거로 해석한 요구 | 미반영 | 미반영 | 조건부 반영 |
| `company_context_signal` | 회사 공식 자료에 반복되나 공고에는 없는 맥락 | 미반영 | 미반영 | 미반영 |

`explicit_requirement`의 범위는 지원자가 갖추어야 할 것과 입사한 뒤 맡을 일이다. 지식·기술·도구, 경험·경력·학력·자격, 태도와 일하는 방식, 맡을 업무와 역할이 여기에 든다. 맡을 일을 함께 담는 이유는 `requiredness`가 `responsibility`를 값으로 갖기 때문이다. 자격 구간만 뽑으면 그 값이 비어 있게 된다.

공고 본문에 있어도 요구로 세지 않는 갈래는 다음과 같다.

```text
회사 소개와 서비스·팀 소개
복리후생과 보상
근무 조건 — 근무지, 근무 형태, 근무 시간, 수습 기간, 계약 기간
전형 절차와 지원 방법, 제출 서류, 문의처
법령 고지
관계 법령에 따른 우대 채용 대상 안내
채용 공정성 안내와 허위 기재 시 합격 취소 안내
개인정보 수집·이용 동의 안내
```

가르는 기준은 지원자가 갖출 수 있는 것인가다. 회사가 제공하거나 정하는 것, 회사가 법에 따라 알리는 것은 `우대`나 `필수`라는 말이 붙어 있어도 요구가 아니다. 같은 말이 들어 있어도 지원자가 갖추어야 할 것이나 맡을 일을 적은 문장이면 요구로 센다. 이 갈래를 요구로 세면 준비할 것이 아닌 차원이 공고에 나타난 것으로 세어져 [지표 명세](metric-spec.md) 3.1의 분자에 들어간다.

회사가 기술 자료에서 자주 다루는 주제와 해당 직무의 채용 요구는 같지 않다. `company_context_signal`은 해당 공고의 명시 요구사항이 아님을 함께 표시하고, 포트폴리오 강조 순서와 면접 준비 후보에만 영향을 준다.

지식 그래프에서 회사 공식 자료의 근거는 요구 차원에 직접 연결하지 않고 분석 주장의 지지 근거로 연결한다.

## 5. 자료·출처·획득 방식

| 계층 | 자료 | 출처 | 획득 방식 | 직접 사용하는 에이전트 |
| --- | --- | --- | --- | --- |
| A | 개별 채용공고 원문 | 기업 공식 채용 페이지 | 수동 큐레이션, 허용 범위 내 정기 수집 | 통계 분석, 채용공고 해석 |
| A | 공고 메타데이터 | 기업 공식 채용 페이지 | 구조 파싱과 수동 보완 | 통계 분석, 채용공고 해석 |
| B | 회사 공식 채용 자료 | 기업 채용 사이트, 공식 인터뷰 | 웹 검색으로 발견 후 원문 수집 | 채용공고 해석, 합격 전략 |
| B | 회사 공식 기술·제품 자료 | 기술 블로그, 개발자 문서, 제품 페이지 | 웹 검색과 원문 수집 | 채용공고 해석, 합격 전략, 준비 로드맵 |
| B | 회사 공식 영상 | 기업 공식 채널 | 영상 검색 후 공개 영상 분석 | 채용공고 해석, 합격 전략, 준비 로드맵 |
| C | 국가직무능력표준 | 공식 공개 자료 | 공개 문서 수집과 구조화 | 통계 용어 연결, 해석, 전략, 로드맵 |
| C | 직무·직업 사전 | 공개 직무·직업정보 자료 | 개인 이용이 허용된 공개 문서 수집 | 통계 용어 연결, 해석, 전략, 로드맵 |
| D | 현직자·면접관 자료 | 공개 웹 자료 | 웹 검색 후 원문 수집과 신뢰도 판정 | 합격 전략, 준비 로드맵, Wiki |
| D | 채용·직무 영상 | 기업 공식·현직자·전문가 채널 | 영상 검색 후 공개 영상 분석 | 합격 전략, 준비 로드맵, Wiki |
| D | 학습·프로젝트 자료 | 공식 문서, 교육 자료 | 웹 검색 후 원문 수집과 신뢰도 판정 | 준비 로드맵 |

포털 채용 사이트는 크롤링하지 않는다. 기업 공식 채용 페이지를 채용공고의 핵심 출처로 사용한다.

### 5.1 영상 자료

영상은 두 단계로 처리한다.

| 단계 | 처리 |
| --- | --- |
| MVP | 자막이 있는 공개 영상의 자막을 근거로 사용한다 |
| 확장 | 영상 메타 수집 API와 영상 분석 모델로 구조화 요약과 주장을 추출한다 |

영상 전체 복제본이나 비공개 자막을 저장하지 않는다. 영상에서 추출한 조언은 준비 전략 근거로 사용하고 공고의 요구사항으로 집계하지 않는다.

영상 처리 절차는 다음과 같다.

```text
영상 후보 검색
→ 채널·작성자·게시일·설명 확인
→ 공개 영상 분석
→ 주장·요약·관련 구간 구조화
→ 자료 계층과 허용 용도 평가
→ 원문 URL과 함께 저장
```

사용자 개인정보, 자기소개서, 비공개 자료를 영상 분석 모델에 입력하지 않는다.

## 7. 원문과 출처 저장

원본은 논리적 출처, 내용 스냅샷, 관찰 기록, 출처 평가로 나눈다. 테이블 정의는 [지식·저장 구조](knowledge-schema.md) 3장에 있다.

동일 URL이라도 내용이 바뀌면 새 스냅샷을 저장한다. 내용 해시가 같으면 기존 스냅샷을 재사용한다. 삭제되거나 접근할 수 없어진 자료도 기존 분석 결과의 근거 추적을 위해 수집 당시의 스냅샷과 관찰 기록을 보존한다.

출처의 계층과 허용 용도는 평가 버전을 가진다. 평가 기준이 바뀌면 새 버전으로 다시 평가하고 이전 평가를 보존한다.

## 8. 조사 정책

웹 검색은 새 자료를 발견하는 도구이며 검색 결과 요약만으로 최종 근거를 만들지 않는다. 선택한 URL의 원문과 메타데이터를 수집하고 허용 용도와 신뢰도를 평가한 뒤 데이터 버전에 포함한다.

### 8.1 접근 정책

수집 대상의 `robots.txt`와 이용 조건을 확인해 `sources.robots_policy`에 기록하고, 다음 순서로 판단한다.

| 신호 | 처리 |
| --- | --- |
| 이용 조건이 수집을 금지한다 | 수집하지 않는다 |
| 대상 경로가 `Disallow`에 있다 | 그 경로를 수집하지 않는다 |
| `Content-Signal`에 `ai-train=no`가 있다 | 원문을 모델 학습과 미세조정에 사용하지 않는다 |
| `Content-Signal`에 `use=reference`가 있다 | 원문을 근거로 인용하고 집계한다 |
| `Content-Signal`에 `use`가 없다 | `use=reference`와 같이 다룬다 |

`use`를 선언하지 않은 출처를 `use=reference`로 다루는 근거는 `Content-Signal` 규약 자체다. 규약은 선언하지 않은 용도에 대해 운영자가 허가도 제한도 하지 않는다고 밝힌다. 명시적 금지가 없으므로 금지로 읽지 않는다.

이용 조건이 `robots.txt`보다 넓은 금지를 두면 이용 조건을 따른다. 자동 접근이 허용되어도 가공·복제·재배포를 제한하는 이용 조건이 있으면 해당 용도로 수집하지 않는다.

`ClaudeBot`이나 `GPTBot` 같은 AI 크롤러 이름을 `Disallow`한 출처는 자동 반복 수집의 대상이 아니다. 같은 출처가 `use=reference`를 선언했거나 `use`를 선언하지 않은 경우 세 조건을 모두 지켜 수집한다.

- 사람이 여는 브라우저 세션에서 지정한 URL을 하나씩 읽는다.
- 원문을 모델 학습과 미세조정에 사용하지 않는다.
- 근거가 되는 `robots.txt` 문구를 수집 매니페스트에 남긴다.

세 조건 중 하나라도 지키지 못하면 해당 출처를 수집하지 않는다.

접근하지 못한 출처는 사유와 함께 수집 매니페스트에 남긴다. 다음 수집이 같은 시도를 반복하지 않는다.

### 8.2 수집 매니페스트

수집 대상의 목록과 출처 메타데이터를 `agent/data/manifest/`의 직무별 파일에 둔다. 파일 하나가 직무 하나의 수집 범위이며 `job_role_id`, `dataset_version`, `as_of_date`, 대상 목록, 접근하지 못한 출처, 접근 방법 기록을 담는다. 백엔드 직무의 범위는 `backend.json`이 담는다. 직무를 늘리면 파일을 더한다.

수집한 원문은 저장소에 두지 않고 데이터베이스 스냅샷에만 넣는다.

매니페스트가 재현의 기준이다. 같은 목록으로 다시 수집하면 같은 자료 범위를 얻는다.

대상 하나는 출처 식별자, URL, 출처 유형, 자료 계층, 허용 용도, 직무, 제목, robots 정책, 수집일, 원문 파일 이름을 담는다. 공고 출처는 회사, 기업군, 게시일, 직무 판정 원문, 대상군 표기 원문과 판정값을 함께 담는다. 직무 판정 규칙은 [지표 명세](metric-spec.md) 2.8, 대상군 표기의 정규화는 같은 문서 2.6에 있다.

출처의 접근 방법은 직무와 무관하다. 직무를 늘릴 때 접근 기록과 접근하지 못한 출처를 직무별 파일에서 공용 파일로 분리한다.

### 8.3 백엔드 직무 수집 결과

`agent/data/manifest/backend.json`은 백엔드 직무에서 확보한 자료 101건과 접근하지 못한 출처 70건을 기록한다.

| 계층 | 확보 건수 | 구성 |
| --- | ---: | --- |
| A | 44 | 기업 공식 채용공고 |
| B | 20 | 회사 공식 채용·기술 자료 |
| C | 2 | 공공·직무 표준 |
| D | 35 | 외부 전문가 자료 29건, 학습 자료 6건 |

A 계층 44건의 대상군 표기는 다음과 같다.

| 대상군 표기 | 건수 |
| --- | ---: |
| `experienced` | 36 |
| `unspecified` | 4 |
| 미표기 | 3 |
| `junior` | 1 |

접근하지 못한 출처에는 이용 조건·라이선스 제한, `robots.txt` 차단, 해당 회사의 백엔드 공고 부재, 신입 필터 결과 없음, 접근 실패와 본문 부재가 포함된다. 개별 URL과 사유는 매니페스트가 소유하고, 자료 확보와 서비스 완성의 순서를 분리한 결정은 [ADR 0017](adr/0017-generated-data-first.md)이 소유한다.

## 9. 데이터셋과 평가 세트

| 데이터 | 정의 | 용도 |
| --- | --- | --- |
| mock | 화면 정보 구조를 검증하는 창작 데이터 | 정적 프로토타입 |
| 생성 데이터 | 규약으로 만든 직무별 공고와 분석 산출물 | 데모 서빙, 화면 검증 |
| 평가 세트 | 대상 공고와 사람이 확정한 정답·루브릭 | 에이전트 품질 평가 |
| 서비스 데이터 | 출처·검증·버전이 있는 실제 자료와 분석 결과 | 배포 서비스 |

생성 데이터의 식별자·테이블·응답 형태 규약은 [생성 데이터 규약](../agent/data/demo_seed/CONTRACT.md)이 소유한다.

평가 세트의 원본은 `docs/eval/`의 JSON 파일이며 사람이 확정한다. 데이터베이스는 평가 실행과 결과 비교에 사용한다. 파일 목록, 정답의 구조, 루브릭 정책, 확정 범위는 [평가 세트](eval/README.md)가 소유한다.

세트의 대상 공고는 실 공고일 수도 생성 공고일 수도 있다. 생성 공고를 대상으로 삼는 세트는 `dataset_version`으로 갈리며 두 세트의 지표를 같은 축에서 비교하지 않는다.

평가 세트는 다음을 담는다.

```text
공고별 기대 요구 표현과 위치
기대 차원과 깊이 등급
해석 루브릭
용어 연결 기준
근거 허용 범위
```

평가 세트의 기대 차원은 분류체계 버전과 독립적인 사람 기준이며, 차원 승격 심사의 채점 기준이 된다.

평가 지표는 다음을 포함한다.

- 요구 표현 추출의 정밀도와 재현율
- 차원 할당 정확도
- 통계 수치와 분모의 일치
- 근거 정확도와 미지원 주장 비율
- 직무·기업군·공고 범위 일치
- 해석에서 체크리스트, 전략, 로드맵으로 이어지는 연결 완전성
- 검색 전략별 근거 기여도

## 10. 데이터 갱신 원칙

- 신규·수정·삭제 공고는 해당 직무의 통계와 영향 범위 분석을 갱신한다.
- 회사 공식 자료는 연결된 직무·기업군·공고의 해석 이후 단계를 갱신한다.
- 공공·표준 자료는 용어 연결과 선수 관계에 영향을 받는 직무를 갱신한다.
- 외부 준비 전략 자료는 합격 전략과 준비 로드맵에만 직접 영향을 준다.
- 분류체계 버전 발행은 해당 직무의 할당 전량과 통계를 갱신한다.
- 사용자 입력 공고는 서비스 통계와 직무 공통 기대치에 포함하지 않는다.

세부 재실행 범위와 버전 활성화 절차는 [아키텍처](architecture.md) 7장을 따른다.

## 11. 보안

- API 키는 환경변수와 배포 환경 비밀값으로 관리한다.
- Express는 조회에 필요한 키만 보유하고, 생성 모델 키는 에이전트 서비스만 보유한다.
- API 키와 수집 원문을 클라이언트 번들과 로그에 노출하지 않는다.
- 웹 검색, 재시도, 토큰 사용량에 실행별 한도를 적용한다.
- 영상 분석 모델에는 공개 자료만 입력한다.
