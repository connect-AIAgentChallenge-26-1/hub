# 개인 회고

> 초안입니다. 사실 정리는 그대로 두고, 느낌·다짐 부분은 내 목소리로 고쳐서 제출하세요.

## 이번 주에 한 것

밥약 서비스의 핵심 흐름을 처음부터 끝까지 완성했다. 모임을 만들고, 친구를 초대하고, 모두의 공강 시간을 자동으로 계산하고, 그 시간에 맞춰 맛집을 추천받아 시간과 장소를 확정하기까지 — 기획서에 그렸던 화면들이 실제로 하나씩 동작하는 걸 보니 뿌듯했다. 원래 이번 주 목표는 공강 계산까지였는데, 계획보다 앞서서 맛집 추천과 UI 다듬기까지 끝냈다.

## AI 에이전트와 함께 개발하면서

이번 챌린지에서 가장 크게 배운 건 "코드를 직접 다 치는 것"보다 **무엇을 어떤 순서로 만들지 정하고, 결과를 검토하고, 방향을 결정하는 것**이 내 역할이라는 점이다. 기술 스택을 고르고(FastAPI + PostgreSQL), 기능을 작게 쪼개 이슈로 만들고, 에이전트가 짠 코드를 PR로 받아 리뷰하고 머지하는 흐름을 반복했다.

처음엔 "알아서 잘 해줘"라고 막연하게 시키면 엉뚱한 결과가 나온다는 걸 몸으로 느꼈다. 그래서 점점 더 구체적으로 — 어떤 화면에, 어떤 조건으로, 끝나면 어떻게 확인하는지까지 — 지시하게 됐다. 계획을 먼저 세우고(Plan), 작게 나눠서 하나씩 검증하는 방식이 훨씬 안정적이었다.

## 이해한 것 / 아직 모르는 것

- **공강 시간 계산**은 이제 설명할 수 있다. 비는 시간을 직접 찾는 게 아니라, 참여자 전원의 바쁜 시간을 합쳐놓고 하루 활동 시간에서 빼면 남는 게 공통 공강이다. 발상을 뒤집으니 풀렸다.
- **아직 JWT 인증 흐름**은 완전히 이해하지 못했다. 로그인하면 토큰이 나오고 그걸로 신원을 확인한다는 큰 그림은 알지만, 서명·검증·만료의 내부 원리는 흐릿하다. 다음에 코드를 직접 읽어보려 한다. 모르는 걸 모른다고 적어두는 것도 다음에 채울 지점을 남기는 일이라고 생각한다.

## 인상 깊었던 순간

- **CSS 변수의 힘.** 색을 처음부터 변수로 써둔 덕분에, 앱 전체 테마를 바꿀 때 파일 딱 두 개만 고쳤는데 모든 화면 색이 한 번에 바뀌었다. "미리 잘 짜두면 나중이 편하다"를 처음으로 실감했다.
- **키 없이도 개발하는 법.** 네이버·카카오 API 키가 없어서 맛집 기능은 못 하겠다고 생각했는데, "키 있으면 실제, 없으면 가짜 데이터" 구조로 화면과 흐름을 먼저 완성할 수 있었다. 외부 준비가 안 돼도 멈추지 않는 방법이 있다는 게 신선했다.
- **엉뚱한 데서 막힌 경험.** 맛집 화면이 자꾸 홈으로 튕겨서 한참 헤맸는데, 알고 보니 옛날 폴더의 서버가 떠 있던 것뿐이었다. 코드가 아니라 "실행 환경"에서 문제가 날 수도 있다는 걸 배웠다.

## 아쉬운 점과 앞으로

- 맛집은 아직 목업 데이터라, 실제 네이버·카카오 API를 연동해봐야 한다.
- AI가 맛집을 골라 "추천 이유"까지 붙여주는 기능은 다음 목표다.
- JWT처럼 "동작은 하는데 원리를 모르는" 부분을 하나씩 직접 읽어 이해로 바꿔가고 싶다.

이번 주는 기능을 완성하는 것 이상으로, **AI와 어떻게 일해야 원하는 결과가 나오는지**를 배운 한 주였다.
