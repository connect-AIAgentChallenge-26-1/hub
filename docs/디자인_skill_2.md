# 밥약 서비스 디자인 Skill (v2)

디자인 결과물(클로드 디자인 시안, Claude Code가 만든 화면)이 내 의도와 맞는지 확인할 때 이 체크리스트를 기준으로 본다.

> **개정 기록**: v1은 "전광판/출발안내판" 어두운 컨셉을 기준으로 잡았지만, 실제 클로드 디자인 결과물은
> 크림톤 배경 + 오렌지 포인트의 따뜻한 톤으로 나왔다. 결과물이 오히려 대학생 대상 서비스에
> 더 잘 맞는다고 판단해, v2부터는 이 결과물을 정식 기준으로 삼는다. (디자인시스템_문서_v2.md와 동기화)

## 1. 컨셉 일관성
- [ ] 크림톤 배경 + 오렌지(`--primary`) 포인트의 따뜻하고 친근한 톤이 느껴지는가?
- [ ] 색상이 디자인시스템_문서_v2.md의 토큰만 쓰였는가? 임의의 색이 섞이지 않았는가?
- [ ] 네이버/카카오 관련 요소에 각 서비스의 실제 브랜드 컬러(초록/노랑)가 쓰였는가?

## 2. 정보 우선순위
- [ ] 화면에서 가장 먼저 눈에 들어와야 할 것(예: 매칭된 시간)이 실제로 가장 눈에 띄는가?
- [ ] 부가 정보(설명 텍스트 등)가 핵심 정보보다 크거나 튀지 않는가?

## 3. 상태 표현
- [ ] "일정 있음 / 개인 공강 / 전원 공강" 세 가지 상태가 색으로 명확히 구분되는가?
- [ ] 매칭된(전원 공강) 상태는 항상 amber 하나로만 표시되어 헷갈리지 않는가?

## 4. 실사용 관점
- [ ] 이 화면을 실제 대학생이 봤을 때, 설명 없이도 무엇을 해야 할지 알 수 있는가?
- [ ] 참여자가 3~4명일 때도 레이아웃이 깨지지 않는가? (많은 사람 수 고려)

## 반복 개선 방법
1. 위 체크리스트로 시안을 점검한다.
2. 마음에 안 드는 항목이 있으면, "왜 안 맞는지"를 한 문장으로 적는다.
   (예: "amber가 너무 튀어서 오히려 정보보다 장식처럼 보인다")
3. 그 문장을 기준으로 시안을 수정하고, 다시 체크리스트로 검토한다.
4. 확정되면 이 skill 파일에 "확정된 규칙"으로 추가해 다음 화면 작업에도 이어간다.

## 실제 반복 사례 (기록)
- **상황**: 처음 정한 디자인시스템(어두운 전광판 컨셉)과 다르게, 클로드 디자인이 밝고 따뜻한 크림+오렌지 톤으로 시안을 만들어옴.
- **판단**: 원래 계획과 다르다고 무조건 다시 만들게 하지 않고, 체크리스트(실사용 관점/정보 우선순위/상태 표현)로 먼저 검증 → 오히려 대학생 대상 서비스에 더 적합하다고 판단.
- **조치**: 원래 컨셉을 버리고, 이 결과물을 새 기준(v2)으로 승격. 디자인시스템 문서와 skill 파일을 실제 결과물에 맞게 업데이트.
- **배운 점**: skill은 "처음 정한 계획을 고집하는 도구"가 아니라, "결과물이 실제로 좋은지 판단하는 도구"로 써야 한다. 계획과 다르다고 반드시 계획에 맞춰 고칠 필요는 없다.
