# ADR 0017. 실 데이터 수집과 서비스 완성의 순서를 분리한다

## 맥락

CareerSignal의 최종 형태는 실제 채용공고와 근거 자료를 정기적으로 수집하고, 자료가 갱신되거나 사용자가 공고를 입력할 때 배포된 에이전트가 분석 산출물을 만드는 구조다. 화면·저장 계약·에이전트 계약은 이 형태를 전제로 한다.

백엔드 직무의 자료를 수집하면서 자료의 이용 조건과 신입 공고 표본이라는 두 제약을 확인했다. `agent/data/manifest/backend.json`에는 확보한 자료 101건과 접근하지 못한 출처 70건의 사유가 기록되어 있다.

접근하지 못한 출처에는 이용 조건이나 라이선스가 가공·재배포를 제한하는 경우와 `robots.txt`가 자동 접근을 막는 경우가 있다. `work24.go.kr` 자료에는 공공누리 제4유형이 적용되고, `docs.oracle.com`과 `dev.java`는 재배포와 자동화 수단 접근을 제한한다. `samsungsds.com`처럼 `robots.txt`보다 이용 조건이 더 넓은 금지를 두는 경우도 있다.

확보한 채용공고 44건의 대상군 표기는 `experienced` 36건, `unspecified` 4건, 미표기 3건, `junior` 1건이다. 신입·주니어 비교 기준의 목표 분모 10건을 충족하지 않는다.

목표 직무 아홉 종의 실 표본을 확보하는 일과 전체 화면·분석·에이전트 실행 경로를 같은 4주 안에 완성하는 일은 동시에 충족되지 않는다.

## 결정

자료 확보와 서비스 완성의 순서를 분리한다.

- 실제 자료로 수집·분석 파이프라인을 검증한다.
- 화면이 조회하는 아홉 직무의 분석 산출물은 같은 스키마와 제약을 통과하는 생성 데이터로 먼저 구성한다.
- 생성 데이터와 실 데이터는 [ADR 0015](0015-generated-dataset-version.md)의 `dataset_version` 규칙으로 구분한다.
- 실 데이터가 충분해진 직무는 새 분석 버전을 검증·활성화해 직무 단위로 교체한다.
- 이용 조건이 `robots.txt`보다 넓은 금지를 두면 이용 조건을 따른다. 접근하지 못한 출처와 사유는 수집 매니페스트에 보존한다.
- 정기 수집, 자료 갱신, 사용자 공고 입력에 따른 에이전트 실행은 최종 설계에 유지한다. 현재 진행 위치는 개발 백로그와 검증 체크리스트가 기록한다.

## 고려한 선택지

| 선택지 | 결과 |
| --- | --- |
| 실 표본이 충족될 때까지 화면과 에이전트 구현을 중단한다 | 자료 확보 속도가 서비스 완성 여부를 결정한다 |
| 이용 조건이 제한하는 자료를 그대로 저장·가공한다 | 출처 정책과 근거 공개가 성립하지 않는다 |
| 백엔드 한 직무만 실 데이터로 제공한다 | 직무를 입력으로 받는 화면과 실행 계약을 전체 범위에서 검증할 수 없다 |
| 실제 자료로 파이프라인을 검증하고 생성 데이터로 전체 경로를 구성한다 | 자료 확보와 서비스 완성을 분리하면서 같은 스키마와 실행 경로를 검증한다 |

## 선택 이유

이용 조건은 자료의 성질이고 신입 공고의 수는 채용 시장의 상태다. 두 조건이 바뀔 때까지 기다리면 서비스 완성이 통제할 수 없는 외부 조건에 묶인다.

생성 데이터는 실 데이터와 같은 표·컬럼·제약을 통과한다. 실 데이터 전환은 직무별 분석 버전을 검증하고 활성화하는 절차로 이루어진다.

## 결과와 제약

- 생성 데이터의 수치는 채용 시장의 사실을 나타내지 않는다.
- 백엔드 실 공고 44건은 파이프라인 검증 표본이며 아홉 직무 화면의 수치는 생성 데이터에서 나온다.
- 신입·주니어 대상군 지표는 표본 상태에 따라 억제한다.
- 실 데이터 전환 전까지 생성 데이터와 실 데이터의 결과를 같은 비교 축에서 평가하지 않는다.
- 수집 결과와 접근하지 못한 출처의 사유는 [데이터 전략](../data-strategy.md) 8장이 요약하고 수집 매니페스트가 원본을 소유한다.
- 정기 수집과 출처 발견의 구현 순서는 [개발 백로그](../backlog.md)가 관리한다.
