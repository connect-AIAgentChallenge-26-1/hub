# ADR 0015. 생성 데이터셋을 `dataset_version`으로 분리한다

## 맥락

화면과 파이프라인은 목표 직무 아홉 종을 전제로 만들어졌다. `0011_job_role_catalog`가 아홉 직무를 기준 데이터로 넣고 `0023_activate_all_job_roles`가 전부 활성화한다. 다섯 화면과 분석 실행 순서는 직무를 인자로 받는다.

아홉 직무 전 범위의 실 공고 표본 확보와 서비스 완성의 순서를 분리한 근거는 [ADR 0017](0017-generated-data-first.md)이 소유한다. 이 문서는 생성 데이터와 실 데이터를 저장·활성화 단계에서 구분하는 방법만 정한다.

백엔드 직무는 실 공고 44건으로 파이프라인을 검증했다. 나머지 여덟 직무는 표본을 채우지 못한다.

## 결정

분석 데이터를 생성 데이터로 채우고 실 데이터와 표시로 가른다.

- 생성 데이터는 전부 `dataset_version = ds_demo_v1`을 갖는다. 분석 버전은 `an_demo_<job>`이다. 실 데이터의 버전 값과 섞지 않는다.
- 코드와 스키마는 생성 데이터를 위해 바꾸지 않는다. 생성 데이터는 실 데이터와 같은 표, 같은 컬럼, 같은 제약을 통과한다.
- 생성 경로는 저장소에 접속하지 않는다. `agent/scripts/build_demo_seed.py`가 직무 조각을 메모리에서 합쳐 표별 CSV로만 낸다.
- 적재는 `agent/scripts/load_demo_seed.py`가 맡고 접속 한 번, 거래 하나로 수행한다. 표마다 `COPY ... FROM STDIN`을 한 번 실행한다. 행 단위 INSERT를 쓰지 않는다.
- 실 데이터 표는 쓰지도 지우지도 않는다. 목록은 `PROTECTED_TABLES`이며 적재 순서와 겹치면 스크립트가 뜨지 않는다.

식별자 규약과 표별 행 수는 [데모 시드 계약](../../agent/data/demo_seed/CONTRACT.md)이 고정한다.

## 고려한 선택지

| 선택지 | 결과 |
| --- | --- |
| 실 데이터를 모을 때까지 직무를 하나로 둔다 | 직무 선택 화면과 직무별 비교가 성립하지 않고 아홉 직무를 전제한 구조가 확인되지 않는다 |
| 화면에 표본 부족을 표시하고 빈 화면을 낸다 | 다섯 화면의 흐름과 조회 경로가 여덟 직무에서 실행되지 않는다 |
| 생성 데이터를 `dataset_version`으로 갈라 적재한다 | 전 직무 흐름이 실행되고 어느 행이 생성 데이터인지가 저장소에 남는다 |

## 선택 이유

버전 축은 이미 스키마에 있다. 생성 데이터를 그 축의 한 값으로 두면 구분에 필요한 코드가 없고, 실 데이터가 들어올 때 같은 축의 다른 값으로 들어온다.

생성 경로를 CSV 출력까지로 끊으면 데이터를 만드는 일과 저장소를 바꾸는 일이 갈린다. 생성물은 적재 전에 파일로 검사할 수 있고, 적재는 거래 하나이므로 결과가 전부이거나 전무다.

## 결과와 제약

- 생성 데이터는 실 데이터의 분포를 재현하지 않는다. 이 데이터에서 읽은 요구 빈도·기업군별 추가 요구·연도 변화는 채용 시장의 사실이 아니다.
- 지표의 표본 상태는 저장된 값 그대로다. 억제된 지표는 억제된 채로 화면에 나타난다.
- 기업군 범위는 최소 표본에 미치지 않는다.
- 백엔드 직무의 실 공고 44건 검증은 파이프라인이 도는 것을 확인한 것이고, 아홉 직무 화면의 수치는 생성 데이터에서 나온다.
- 실 데이터가 쌓이면 직무 단위로 교체할 수 있다. 교체는 그 직무의 새 분석 버전을 활성화하는 일이다.
- 되돌리기는 `dataset_version = 'ds_demo_v1'`이거나 `analysis_version LIKE 'an_demo_%'`인 행만 지운다. 두 표시를 갖지 않는 표는 임시 표로 모은 대상 식별자로만 지운다. 조건 없는 DELETE가 없다.
- `knowledge_nodes`·`knowledge_edges`의 참조 노드와 `requirement_taxonomies`는 실 데이터와 신원을 공유한다. 적재는 이미 있는 행을 만들지 않고 채택하며, 되돌리기가 그 행을 지우지 않는다.
