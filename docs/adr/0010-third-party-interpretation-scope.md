# ADR 0010. 제3자 자료를 해석의 보강 근거로 사용한다

## 맥락

[데이터 전략](../data-strategy.md) 3장은 D 계층의 해석 용도를 `교차 확인에만 사용`으로 둔다. [에이전트 설계](../agent-design.md) 8장의 주장 유형 일곱 가지에는 교차 확인에 해당하는 자리가 없다. 교차 확인의 결과를 어느 주장으로 기록하는지가 두 문서 어디에도 없어, D 계층 자료를 수집해도 해석 단계에서 쓸 경로가 없다.

[ADR 0009](0009-third-party-reliability.md)가 D 계층의 편입을 내용 판정으로 넓혔으나, 편입된 자료의 사용처는 준비 전략과 준비 로드맵에 머문다.

백엔드 데이터셋의 채용공고는 44건이다. 추론 요구를 공고 표현과 회사 공식 자료만으로 보강하면 보강 근거를 찾지 못한 추론이 대부분 폐기된다.

## 결정

D 계층의 해석 용도를 `사용`으로 바꾼다.

- 추론 요구의 보강 근거로 D 계층 자료를 사용한다. 출발점은 공고 표현이며 D 계층 자료만으로 추론 요구를 세우지 않는다.
- 사용한 근거의 `reliability_score`를 주장과 함께 기록한다.
- 통계 집계의 경계는 바뀌지 않는다. A 계층만 분자와 분모에 들어간다.
- Wiki 필드별 허용 근거는 바뀌지 않는다. 정의는 [지식·저장 구조](../knowledge-schema.md) 8.5에 있다.
- E 계층은 후보 탐색에만 사용한다.

## 고려한 선택지

| 선택지 | 결과 |
| --- | --- |
| 교차 확인의 정의를 새로 만든다 | 주장 유형이 여덟 개가 되고 검증·신뢰도·화면 계약이 함께 늘어난다 |
| D 계층을 해석에서 제외한다 | 수집한 자료가 준비 전략 밖으로 나가지 못하고 추론 요구가 비어 있다 |
| 해석 용도를 `사용`으로 바꾼다 | 보강 근거가 늘고 통계 경계는 그대로다 |

## 선택 이유

교차 확인은 용도가 아니라 검증 절차의 이름이다. 자료 계층 표는 용도를 정하는 자리이므로 절차 이름을 두면 사용처가 정해지지 않는다.

보강과 지지를 구분하면 자료를 넓히면서도 주장의 출발점을 공고에 묶어 둘 수 있다. 근거의 수가 아니라 근거의 자리가 주장의 성격을 정한다.

## 결과와 제약

- 추론 요구는 공고 표현이 없으면 성립하지 않는다. D 계층 근거만 가진 주장은 미지원 주장으로 센다.
- 근거 허용 범위의 채점 기준은 `docs/eval/rubrics_v1.json`의 `rb_evidence_tier_scope`가 담는다.
- 신뢰도가 기록되지 않은 D 계층 자료는 근거로 사용하지 않는다. [ADR 0009](0009-third-party-reliability.md)의 제약이 그대로 적용된다.
- 통계 수치와 기업군 일반화, 추가 요구 없음 주장은 A 계층 근거만 받는다.
