# 밥약 매칭 서비스 - 설계 문서

## 한 줄 정의
대학생 4명 정도가 각자 캘린더(에타/구글/애플)를 연결하면 공강 시간을 자동으로 찾아주고,
위치 + 음식 카테고리 입력 시 네이버/카카오 기반 맛집을 추천해주는 서비스

## 핵심 흐름
1. 로그인/회원가입 → 본인 캘린더(에타/구글/애플) 연동 (한 번 연결하면 계속 재사용)
2. 밥약 모임 생성 → 참여할 친구 초대
3. 참여자 전원의 캘린더 기준으로 공강 시간 자동 계산
4. 위치(GPS 또는 학교 이름) + 음식 카테고리 입력
5. 네이버 + 카카오 로컬 API 결과를 합쳐 리뷰순/평점순으로 맛집 3~4곳 추천

## ERD

```
USER ||--o{ CALENDAR_INTEGRATION : connects
CALENDAR_INTEGRATION ||--o{ EVENT : provides
USER ||--o{ MEETUP_SESSION : creates
MEETUP_SESSION ||--o{ SESSION_PARTICIPANT : includes
USER ||--o{ SESSION_PARTICIPANT : joins

USER {
  uuid id PK
  string name
  string email
}
CALENDAR_INTEGRATION {
  uuid id PK
  uuid user_id FK
  string provider        // "google" | "apple" | "everytime"
  string external_calendar_id
}
EVENT {
  uuid id PK
  uuid integration_id FK
  string title
  datetime start_time
  datetime end_time
}
MEETUP_SESSION {
  uuid id PK
  uuid creator_id FK
  string location_name
  string food_category
  datetime created_at
}
SESSION_PARTICIPANT {
  uuid id PK
  uuid session_id FK
  uuid user_id FK
}
```

## 외부 연동

| 연동 대상 | 방식 |
|---|---|
| 구글 캘린더 | OAuth 로그인 → Google Calendar API |
| 애플 캘린더 | CalDAV + iCloud 앱 암호 |
| 에타 시간표 | 공유 링크 identifier로 시간표 데이터 파싱 |
| 네이버 맛집 | 네이버 검색 Open API (지역검색), 리뷰순 정렬 |
| 카카오 맛집 | 카카오 로컬 API, 두 결과 합쳐서 표시 |

## 4주 로드맵

| 주차 | 내용 |
|---|---|
| 1주 | 기획/설계 완료 (ERD, 화면 목록), 회원가입/로그인 |
| 2주 | 캘린더 연동 (구글 우선 → 애플 → 에타) |
| 3주 | 밥약 모임 생성 + 공강 시간 자동 계산 로직 |
| 4주 | 네이버/카카오 맛집 추천 연동 + UI 다듬기 (배포는 여유 있으면) |

## 진행 방식
- 팀원 없이 개인 진행
- 배포는 필수 아님 (시간 되면 진행)
- 우선순위: 캘린더 연동 + 공강 계산 (핵심) > 맛집 추천 > UI 다듬기 > 배포(선택)
