# 잔소리봇 — 리서치 & 아이디어 정리

> 회피/미루기 습관을 가진 사용자를 위한 AI 동행 서비스. 사용자가 입력한 회피 이유를
> 확인하고 가장 작은 첫 행동(마이크로태스크)을 제안하며, 레벨(Lv1~Lv4)에 따라
> 개입 강도를 조절합니다.
>
> 이 문서는 초기 기획·디자인 단계에서 경쟁 서비스와 시각 방향을 조사한 기록입니다.
> 외부 서비스에 관한 내용은 조사 당시 기준이며 현재 상태를 새로 검증하지 않았습니다.
> 현재 최종 디자인은 `docs/design-concept.md`와 실제 구현을 따릅니다.

## 1. 조사한 유사 서비스 정리

아래 비교는 조사 당시 관찰과 판단을 보존한 것입니다.

| 앱                                    | 핵심 메커니즘                        | 특징                                                                                | 규모 / 참고                                             |
| ------------------------------------- | ------------------------------------ | ----------------------------------------------------------------------------------- | ------------------------------------------------------- |
| **터닝 (Turning)**                    | 스크린타임 관리 + 캐릭터 상태 변화   | 스마트폰 사용 패턴에 따라 캐릭터 '터니'의 상태가 변함. 앱 잠금 중심                 | 160개국 25만 명 사용, 국내 스크린타임 앱 1위            |

| **FocusFlight**                       | 비행 테마 (Focus Traveller 계열)     | 항공/여행 소재로 뽀모도로 감쌈                                                      | 소규모, 틱톡 챌린지 중심                                |
| **카페 뽀모도로류** (Coffee Focus 등) | 커피 추출 애니메이션 + 바리스타 등급 | 세션마다 XP 획득                                                                    | 유사 앱 다수, 카테고리 자체가 포화                      |
| **Duolingo**                          | 스트릭 손실회피 + 감정적 알림        | 1인칭 말투 알림, 상황별 문구(경쟁/마감/애착), 장기 무시 시 "포기 선언" 후 알림 중단 | 학습앱 게이미피케이션의 대표 사례                       |
| **Todoist**                           | Karma 포인트 + 생산성 그래프         | 완료·목표 달성 시 포인트 적립, 색상 그래프로 트렌드 시각화                          | 게이미피케이션이 단순한 편, 업계 기본 기준선            |
| **투두메이트 (TodoMate)**             | SNS형 투두리스트 + 마스코트          | 친구 팔로우 후 완료 기록에 이모지 응원. 마스코트는 디자이너의 반려견에서 착안       | 포브스 코리아 생산성 앱 15위, 사용자 다수가 10~20대(MZ) |
| 2Planner                              | (검색으로 명확히 확인 안 됨)         | —                                                                                   | 추가 조사 필요                                          |

### 핵심 인사이트

- **Forest / Duolingo**: "미루면 잃는다"는 손실회피 — 잔소리봇의 압력 게이지와 철학적으로 가장 가까움. 단, 이미 대형 서비스가 선점한 컨셉이라 그대로 가져오면 카피처럼 보일 위험.
- **Finch**: "완료 → 캐릭터/오브젝트가 반응"하는 구조가 잔소리봇의 "회피 이유 물어보기"와 구조적으로 유사 — 확장하기 쉬움.
- **Focus Town / Focus Traveller**: "함께 하기(실시간 동시접속, 그룹)"가 핵심 동력. 스코프가 커서 MVP 단계엔 부담.
- **카페 뽀모도로류**: 이미 유사 앱이 너무 많아 차별화 어려움 → 참고에서 제외.
- **투두메이트**: 정교한 3D 캐릭터가 아니어도 "개인적 사연이 담긴 단순한 마스코트"로 충분히 애착 형성 가능하다는 사례.

### 현재 제품과의 연결

잔소리봇은 손실회피나 경쟁을 강하게 적용하지 않고, 회피 이유 확인 → 작은 첫 행동
제안 → Lv1~Lv4 개입 → Focus → History의 흐름으로 차별점을 구현했습니다. 캐릭터는
보상 수집 대상보다 사용자의 실행을 함께 돕는 AI 동행자로 사용합니다.

## 2. 초기 집중력·게임화 브레인스토밍

| 아이디어                       | 요약                                                | 상태                                                 |
| ------------------------------ | --------------------------------------------------- | ---------------------------------------------------- |
| 미룸이 보이는 정원 (화분/식물) | 회피 시 시들고, 빨리 시작할수록 무성해짐            | 검토 후 보류                                         |
| 비행 기록 (여정 로그/항로)     | 할일=비행, 지연 이륙 기록, 완료 시 항로 누적        | **제외** (사용자 비선호, 스코프 큼)                  |
| 캐릭터 마을 (Focus Town식)     | 캐릭터/마을이 함께 발전                             | 보류 (차별화 약함, 스코프 큼)                        |
| 씨앗 발아                      | 마이크로태스크 완료 = 물 한 방울                    | **제외** (정원 아이디어와 중복)                      |
| 잔소리봇 길들이기              | 시작 속도에 따라 봇 말투가 누그러짐/집요해짐        | 보류 (순한맛/중간맛/매운맛 톤 선택 기능과 충돌 가능) |
| 온도계/날씨 강화판             | 기존 압력 게이지를 날씨로 리스킨                    | **채택 → 최종 방향으로 발전**                        |
| 책상 위 오브젝트 컬렉션        | 완료마다 책상에 오브젝트가 쌓임                     | 후보 (제작 부담 있음)                                |
| 퍼즐/도미노 조각 맞추기        | 마이크로태스크 완료마다 조각이 맞춰짐               | 후보                                                 |
| 출석 도장판                    | 완료마다 도장이 찍힘                                | 후보 (저비용)                                        |
| 책장 채우기                    | 완료 과목별로 책이 책장에 꽂힘                      | 후보 (저비용)                                        |
| 발자국 여정 (로컬 산책로)      | 완료 개수만큼 디딤돌에 불이 켜짐                    | **채택 → 최종 방향에 통합**                          |
| 알 까기                        | 시작 빠를수록 알에 금, 완료 시 부화 → 캐릭터 컬렉션 | 후보 (Finch류와 유사)                                |

### 향후 테마/모드 확장 후보 (MVP 이후 로드맵용, 브레인스토밍만 해둔 상태)

- 탐험가 모드 (등산/정글)
- 우주비행사 모드 (헬멧, 우주 배경 — 야간 공부러에 적합)
- 선원/항해사 모드 (파도 항해, 날씨 컨셉과 자연스럽게 연결)
- 정원사 모드 (밀짚모자, 꽃 피는 여정 — 힐링 톤)
- 택배기사/배달원 모드 (가벼운 유머 톤)
- 계절 테마 (벚꽃/여름바다/단풍/눈 — 제작 부담 적음, 시즌 마케팅용)
- 도시/네온 모드 (야간 공부러 타겟)
- 미니멀 모드 (캐릭터/배경 끄고 숫자·그래프만, 접근성 옵션)

> 결론: 지금은 여러 모드를 만드는 대신 **하나의 세계관(날씨+여정)을 완성**하고, 커스터마이징은 세계관 전체 교체가 아니라 스카프 색·배지 같은 **장식 레이어**로 먼저 시작하는 것을 권장. 위 모드들은 유저 반응 확인 후 하나씩 확장.

현재는 날씨+여정 세계관만 Shared Journey로 반영했습니다. 정원, 비행, 마을,
컬렉션, 경쟁과 커스터마이징은 구현하지 않았으며 초기 아이디어로 남겨 둡니다.

## 3. 날씨 + 여정 통합 시스템

> 아래 서사와 시간대 테마는 초기 디자인 가설입니다. 실제 최종 반영 범위는 이어지는
> 표에서 구분합니다.

**초기 서사 구조**

1. **출발 전 (Lv1~4, 기존 압력 게이지 대체)**: 할일을 미룰수록 하늘이 흐려짐 (맑음 → 흐림 → 비 → 폭풍), 레벨별 잔소리봇 개입 강도도 함께 상승
2. **출발 (시작하기 버튼)**: 비가 그치고 해가 나기 시작 — 별도의 진행률 계산 없이 "시작했다"는 이벤트 하나로 전환
3. **여정 중 (포커스 타이머)**: 날씨가 개어가는 상태 유지, 잔소리봇이 목적지를 향해 걷는 연출
4. **도착 (완료)**: 완전히 갬 + "야호!" — 여정의 클라이맥스, 보상 지점

**조사 당시 결정 이유**: 압력 게이지(경고)와 완료 보상(긍정 피드백)을 하나의 데이터(레벨/완료 여부)로 표현할 수 있어 개발 부담이 적고, "잔소리→실행→도착"이라는 서비스의 핵심 서사를 그대로 시각화할 수 있다고 판단했습니다.

**시간대 배경 4테마 초기 시안 (2026-07-19 조사 당시)**

| 테마             | 시간대 | 시각        | 근거                                                           |
| ---------------- | ------ | ----------- | -------------------------------------------------------------- |
| 1. 라이트&소프트 | 새벽   | 04:00~07:00 | 연하고 은은한 톤                                               |
| 2. 비비드 라이트 | 오전   | 07:00~12:00 | 채도 높고 쨍쨍함                                               |
| 3. 비비드 스트롱 | 오후   | 12:00~18:00 | 강한 대비, 선명함                                              |
| 4. 딥&네온       | 밤     | 18:00~04:00 | 다크 네이비+네온 (5번 섹션의 Apple Watch 레퍼런스와 동일 계열) |

오후→밤 전환 구간(약 17:00~19:00)에 노을 오버레이(웜옐로 포인트, 위 표의 "포인트" 컬러) 적용, 별도 5번째 테마로 만들지 않음.

시간대(배경) ↔ 날씨/레벨(오버레이)은 분리된 레이어로 설계해 조합 폭발을
방지하려 했습니다. 이 시간대·오버레이 합성 방식은 최종 제품에 구현하지 않았습니다.

### 초기 가설과 최종 반영

| 조사 단계의 가설 | 최종 반영 | 상태 |
| --- | --- | --- |
| 레벨을 날씨 변화로 표현 | Lv0 맑음 → Lv1 구름 조금 → Lv2 흐림 → Lv3 비 → Lv4 폭풍 배경 | 반영 |

## 4. 캐릭터 디자인 결정 과정

- **1차 시도**: 손그림 기반 각진 블록형 로봇(사각 몸통+원형 머리+막대 팔다리). 표정(눈썹 각도, 이빨 모양)으로 레벨을 표현하되, 색은 신호등(초록~빨강) 대신 날씨 팔레트로 재매핑.
- **최종 방향 전환**: 사용자가 참고한 3D 렌더 이미지 기준으로, **배가 나온 통통한 글로시 화이트 로봇**으로 변경. 구성 요소: 안테나(발광), 통짜 검은 스크린 얼굴, 링 형태 귀, 스카프 매듭, 스터비한 팔다리.
- **표정 시스템 초기안**: 얼굴 스크린의 눈·눈썹·입 모양과 색을 바꾸어 Lv1~Lv4를 표현하고, 몸통은 최대한 일관되게 유지하는 방향을 검토했습니다.
- **제작 과정**: 이미지 생성 AI로 변형할 때 원본 참고 이미지를 함께 사용해 캐릭터 일관성을 높이는 방식을 택했습니다. 벡터 기본형과 표정 데이터 분리안은 구현하지 않았고, 최종 화면은 전신·얼굴·Walking·성공 상태별 PNG 에셋을 사용합니다.
- **커스터마이징 초기안**: 스카프 색상 같은 장식 레이어부터 확장하는 방안을 검토했지만 현재 구현 범위에는 포함하지 않았습니다.

## 5. 디자인 톤 관련 조사와 최종 반영

| 검토한 레퍼런스 | 조사 당시 판단 | 최종 반영 |
| --- | --- | --- |
| 하늘색+화이트+글래스 | 흔한 AI 팔레트는 피하고 재질감을 참고 | 밝은 패널과 여백을 사용하고 blur는 Journey 정보 패널 등 제한된 영역에만 적용 |
| 보라+블루 블러 SaaS 대시보드 | 흔한 AI 템플릿 인상을 피하기 위해 제외 | 강한 네온·유리 효과를 사용하지 않음 |
| 사실적 하늘·들판과 프로스티드 카드 | 프리미엄한 배경 표현에 참고 | Shared Journey 배경과 읽기 쉬운 정보 패널에 반영 |
| 다크 네이비와 시안 글로우 | 집중 화면 후보로 검토 | 최종 Focus는 레벨별 Journey 배경과 밝은 정보 패널을 사용해 미반영 |

특정 브랜드나 서비스를 복제하지 않고, 미니멀한 정보 위계, 충분한 여백과 차분한
깊이감만 참고했습니다.

## 6. 현재 최종 디자인과 연결

- **최종 방향**: Calm, Premium, Warm을 바탕으로 한 AI 동행자 경험
- **개입 표현**: 회피 이유 기반 Lv0~Lv4 개입을 캐릭터, Badge 색과 날씨로 연결
- **Shared Journey**: Landing의 개념 소개, Home Hero, Focus 배경·Walking 포즈,
  Completion 성공 경험에 적용
- **화면 구현**: Landing, Register, Home, Nudge Modal, Focus, Completion, History
- **반영하지 않은 초기안**: 시간대 테마, 실제 걷기·도착 애니메이션, 강한 게임화,
  경쟁·수집·커스터마이징

현재 상세 디자인 규칙은 `docs/design-concept.md`, 화면 구조와 이동은
`docs/wireframe.md`, 실제 UI 작업 기준은 Nagging Bot Design Skill을 따릅니다.
