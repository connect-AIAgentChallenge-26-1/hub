## 오늘 한 일

이번 주 밥약의 **핵심 사용자 흐름을 끝까지 완성**했다. 모임 생성부터 친구 초대, 공강 시간 계산, 시간·장소 확정까지 — 디자인 시안의 6개 화면이 전부 실제로 동작한다.

- 3주차 개발: Feat-1(모임 생성) · Feat-2(친구 초대/수락) · Feat-3(공강 계산) · Feat-4(시간 확정)
- UI 다듬기: 앱 전체를 디자인 시안(밝은 귤색 캠퍼스 테마)으로 통일
- 4주차 착수: Feat-5(맛집 추천) · Feat-6(장소 확정 + "밥약 확정!" 화면)
- 챌린지 제출 PR(#947) 작성

기능마다 `이슈 → feat 브랜치 → dev PR → 리뷰·머지 → 이슈 close` 워크플로우를 지켰고, PR 전 보안 점검도 매번 했다.

## 잘된 점

- **워크플로우를 끝까지 지켰다.** 급해도 main에 바로 커밋하지 않고, 기능마다 이슈를 만들고 PR로 올려 머지했다. 나중에 뭘 왜 했는지 이력이 깔끔하게 남았다.
- **CSS 변수 덕을 크게 봤다.** UI 테마를 바꿀 때, 그동안 색을 변수(`--accent` 등)로 써둔 덕분에 파일 딱 2개만 고쳤는데 앱 전체 색이 한 번에 바뀌었다. "미리 잘 짜두면 나중이 편하다"를 체감했다.
- **순수 함수 + 단위 테스트.** 공강 계산을 DB와 분리해서 짜니, 겹치는 일정 같은 까다로운 경우를 테스트로 빠르게 검증할 수 있었다.

## 어려웠던 점 / 막혔던 점

- **엉뚱한 서버가 떠 있어서 헤맸다.** 맛집 화면을 확인하는데 자꾸 홈으로 튕겼다. 알고 보니 5173 포트에 예전 폴더(`naver-ai-challenge`)의 옛 프론트 서버가 돌고 있어서, 새로 만든 모임 페이지 주소를 몰랐던 것. 그 서버를 끄고 `hub/prototype` 서버를 띄우니 해결됐다. → 앞으로 앱 실행은 꼭 `~/hub/prototype`에서.
- **브랜치 순서를 조정해야 했다.** 맛집 UI를 만들려고 브랜치를 땄더니 방금 만든 귤색 테마가 없어서, 맛집 화면이 옛 보라색으로 보였다. UI 테마 PR을 먼저 머지하고 그 위에서 맛집을 개발하니 시안 톤으로 맞았다. "무엇을 먼저 합쳐야 하는지" 순서가 중요하다는 걸 배웠다.

## 배운 것 / 새로 알게 된 것

- **여집합으로 공강 구하기.** 비는 시간을 직접 찾는 게 아니라, 다들 바쁜 시간을 합쳐서 활동 시간에서 빼면 된다는 발상.
- **키 없을 때 목업으로 개발.** 네이버/카카오 API 키가 없어도, "키 있으면 실제 / 없으면 가짜 데이터" 구조로 화면과 흐름을 먼저 완성할 수 있었다. 외부 의존성이 준비 안 돼도 개발을 멈추지 않는 방법이 있다는 게 오늘 가장 큰 수확.

## 아직 아쉬운 / 모르는 것

- **JWT 인증 흐름**은 동작은 하는데 내부 원리(서명·검증·만료)가 아직 흐릿하다. 다음에 `core/security.py`를 차근히 읽어보자.
- 맛집은 아직 **목업 데이터**다. 네이버/카카오 키를 발급받아 실제 연동을 해봐야 한다.
