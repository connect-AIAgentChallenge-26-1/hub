# 내부 상태 에이전트 테스트 계획

## 핵심 계약

- 내부 상태 여섯 차원은 각각 0~1 범위이며 합계 정규화를 요구하지 않는다.
- 클라이언트가 상태값, 상태 델타, 선택 행동, 판단 추적을 지정할 수 없다.
- 같은 이전 상태와 같은 입력은 같은 행동을 선택한다.
- 같은 요청 ID는 새 상태 전이를 만들지 않고 저장된 결과를 재생한다.
- 상태 버전 충돌 시 최신 상태로 한 번 재계산하고 재충돌은 `409`로 반환한다.

## 화면

- 초기 화면에 로봇 내부 상태 차원과 입력 대기 상태가 표시된다.
- 메시지는 최대 1,000자로 제한된다.
- Enter는 전송하고 Shift+Enter는 줄바꿈한다.
- 처리 중에는 중복 제출이 차단된다.
- 응답에는 선택 행동과 문장만 표시된다.
- 오류는 접근 가능한 알림으로 표시된다.
- 메시지 기록은 `role="log"`와 `aria-live="polite"`를 유지한다.

## 서버와 저장

- `POST /api/agent-interactions`가 요청 UUID와 메시지를 검증한다.
- 원자적 RPC가 에이전트, 상호작용, 스냅샷, 선택적 기억을 함께 갱신한다.
- 내부 판단 추적은 공개 DTO에 포함되지 않는다.
- 기능 플래그가 꺼져 있으면 신규 API는 `404`다.
- JSON 오류, 본문 크기, CORS, 요청 제한 응답이 안정적이다.
