# 고도화 계획과 고민

## 1. 신뢰할 수 있는 참여 구조

- 네이버 로그인을 추가해 후보 포토스팟 제안자와 좋아요 사용자를 연결한다.
- 사용자와 관리자 역할을 분리하고, 후보 스팟은 관리자 검토 뒤에만 공식 스팟으로 승격한다.
- 검토 결과와 사유를 남겨 장소·가이드 품질을 운영 가능하게 만든다.

## 2. 포토스팟·가이드 데이터 확장

- 더 많은 지역과 프레임을 추가하되, `photo_spots`와 `photo_guides`를 분리한 현재 데이터 모델을 유지한다.
- 목록 화면은 지도 범위·상태·페이지 단위로 조회하고, 프레임·가이드·이미지 URL은 상세 진입 때 지연 로딩한다.
- 사진 원본과 Overlay PNG는 Storage에, 검색·권한·좌표·가이드 JSON은 DB에 저장해 대용량 파일과 조회 데이터를 분리한다.

## 3. 대규모 데이터에 대한 고민

포토스팟과 가이드가 늘면 모든 마커와 가이드를 한 번에 내려받는 방식은 지도 초기 로딩과 DB 조회 비용을 키운다. 실제 사용량을 측정하며 상태·좌표 복합 인덱스, 지도 범위 검색, 커서 기반 페이지네이션을 먼저 적용하고, 지역 규모가 충분히 커지면 공간 인덱스와 클러스터링을 단계적으로 검토한다.

Vision 분석도 모든 촬영에 무거운 배경 정합을 실행하지 않는다. 기본은 저장된 기준 관절점과 새 촬영 사진의 YOLO Pose를 비교하고, 정확도가 필요한 경우에만 관리자 승인 배경선 주변의 ORB/RANSAC 비교를 사용한다.
