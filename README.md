# hub
# 소상공인 음식점 운영 보조 Agent

## 프로젝트 주제

소규모 음식점의 주문 데이터를 활용하여 테이블별 예상 이용시간과 대기시간을 계산하고, 단순 매출만으로는 알기 어려운 운영상의 손실을 찾아주는 Agent를 만들고자 합니다.

현재는 아이디어를 구체화하는 단계이며, 사용자 조사와 구현 가능성을 확인한 뒤 기능의 범위를 조정할 예정입니다.

## 문제 상황

웨이팅이 있는 소규모 음식점에서는 직원이 매장 상황을 직접 확인하여 손님에게 예상 대기시간을 안내하는 경우가 많습니다.

하지만 테이블마다 주문한 메뉴와 주문 시간이 다르고, 메뉴별 조리시간과 식사시간도 달라 정확한 대기시간을 안내하기 어렵습니다.

또한 POS에서는 매출과 인기 메뉴를 확인할 수 있지만, 다음과 같은 손실은 쉽게 파악하기 어렵습니다.

- 많이 팔리지만 원가가 높아 실제 이익이 적은 메뉴
- 조리시간이 길어 다른 주문까지 지연시키는 메뉴
- 할인, 수수료, 재료비, 인건비를 제외하면 이익이 적은 주문
- 테이블 회전이 늦어 발생하는 운영상의 손실

## 해결 아이디어

주문 시간, 테이블 번호, 주문 메뉴, 메뉴별 평균 조리시간 등의 데이터를 활용하여 다음 정보를 제공하고자 합니다.

1. 테이블별 예상 식사 완료시간 계산
2. 대기 손님의 예상 입장시간 안내
3. 메뉴별 매출이 아닌 실제 수익성 비교
4. 주문 지연이나 병목을 발생시키는 메뉴 탐지
5. 가격, 할인, 메뉴 구성 변경에 따른 결과 비교

## 초기 MVP 기능

첫 번째 버전에서는 다음 기능을 중심으로 구현할 예정입니다.

- 테이블별 주문 정보 입력
- 메뉴별 예상 조리시간 설정
- 주문시간을 바탕으로 예상 테이블 이용시간 계산
- 현재 대기 팀의 예상 입장시간 표시
- 메뉴별 판매가와 원가를 활용한 예상 이익 계산

실제 POS 연동은 초기 범위에서 제외하고, 샘플 주문 데이터를 활용해 핵심 기능을 구현하고 테스트할 예정입니다.

## 기대 효과

- 대기시간 안내의 정확도 향상
- 대기 손님의 이탈 감소
- 테이블 운영과 주문 처리 상황을 한눈에 확인
- 매출은 높지만 실제 이익이 낮은 메뉴 발견
- 소상공인의 운영 판단에 필요한 정보 제공

## 앞으로 확인할 내용

- 실제 소규모 음식점에서 가장 불편하게 느끼는 문제가 무엇인지
- 대기시간 예측과 수익성 분석 중 어떤 기능의 필요성이 더 높은지
- 개인 프로젝트에서 구현 가능한 데이터와 기능의 범위
- 실제 매장 데이터 없이도 효과를 검증할 수 있는 방법
